## 1. What done looks like

| Situation | Required user experience |
| --- | --- |
| Open a saved chat for the first time | The newest readable prompts and replies appear as soon as the selected history read returns. A cold launch, no cached page, or a very long older history must not turn this into a whole-chat load. A known chat can open before the sidebar finishes. Opening does not run the model or wait for live permissions, Stop, recovery UI, children, media details, or the rail index. |
| Revisit or switch chats | Reuse the authorized settled window and its scroll anchor on a warm revisit; refresh it without blanking or moving it. An older response from a different chat, navigation request, or history incarnation cannot take over the view. Without a saved view position, open at the latest activity. |
| Draft or change a composer setting | Keep the editor and caret stable while history or settings refresh. Switching back restores that chat's unsent draft. Model, effort, and working-folder choices update immediately for the **next turn**, even during a run. Permission mode responds immediately to selection without claiming unconfirmed access. There is no normal settings-loading step between choosing and pressing Send, and no picker reloads the conversation. |
| Send, Queue, Steer, or Stop | Show which action will happen before it is taken. Send starts one new turn; Queue retains a follow-up above and outside the input; Steer applies to the selected active turn; Stop interrupts owned work without losing unrelated draft or queue content. Uncertain delivery does not invite a duplicate send. |
| Use the left prompt rail | Reach any **saved user prompt**, even if its message or turn has never been fetched. See a recognizable label or a lazily loaded preview; select an exact prompt, not just its approximate turn. Group crowded markers without hiding access to individual prompts. On mobile the existing prompt navigator list uses the same history and jump behavior; no desktop rail layout is required. |
| Read around an older prompt | Land on and highlight that prompt. Continue scrolling **older and newer** from there, with no silent gap. “Go to latest” fetches or restores the actual tail, not the bottom of the old window. Incoming output can signal new activity without moving the reader; following resumes only when they return to the tail. |
| Open an active or interrupted chat | Read settled history independently. Live state can show “checking”, “unavailable”, or the current run. Send, Stop, consent, and recovery actions stay server-authoritative; an unavailable state is not “idle”, “denied”, or permission to act. A lost send response can still be reconciled against canonical admission without sending twice. |
| Restart, compact, fork, or delete | Existing readable history and supported detail survive restart and model-context compaction. Forks retain their own lineage; deleted or replaced conversations cannot reappear via cached rows, links, or cursors. Required display facts and authorized media survive any storage change. |

There are two separate acceptance gates: **chat-page behavior (history and composer)** and **transcript consolidation**. Qualify the first with the existing transcript still readable. The second requires retiring the duplicate full-history writer for the new format, not just documenting the old writer. Distinct display facts may remain durable if their ownership is explicit. Audio dictation is a composer input, not that transcript.

## 2. Why paging and caching alone do not meet this contract

- **A page is not a bounded read.** The same 40 UI rows took 48 vs. 480 canonical events and 72 vs. 720 decoded transcript rows for 24 vs. 240 settled turns; no legacy repair ran. The [history handler][kohaku-history-read] reads a full source snapshot, and [page selection][kohaku-history-page] decodes chunks before selecting turns. Failing only the live permission projection made valid history return 503. Startup recovery and sidebar misses also scan old history; attaching a socket can repeat the full source read. Smaller page sizes and a warm cache cannot remove those costs.
- **Fetching an old page is not navigating to a prompt.** The [rail][kohaku-rail] starts an index walk on partial history, depends on the visible DOM even when older prompts exist, and keys unloaded markers by an empty list of row IDs. [The jump hook][kohaku-jump] replaces the page with one ending at a bare turn ordinal. It does not carry the requested prompt through mount and scroll, or provide a newer cursor. A turn can also contain more than one user input; a turn count is not a prompt index. [The current viewport test][kohaku-jump-test] checks that a cursor callback fires, not that the selected prompt lands in view.
- **The relevant Codex Desktop design is selective reveal.** In installed build `26.1111.71704`, the renderer has a recent summary hydration path and a separate background rail query that can fetch turn positions without items. An unloaded rail entry resolves a stable turn/item, loads the target, waits for its rendered anchor, and cancels superseded reveals. The inspected rail path admits partial coverage; it does not require a full item history before opening. The [App Server contract](https://learn.chatgpt.com/docs/app-server#list-thread-turns) likewise separates saved reads from resuming work. Copy that behavior, not the internal page sizes or state model.

## 3. Boundaries and read contracts

Reuse the existing gateway, authentication, and client transport. These are responsibilities, not new services.

| Owner | Contract |
| --- | --- |
| **Catalog** | Session identity, title, bounded preview, and activity metadata. Update rows from committed metadata or a bounded read. A display-only activity update must not rescan unchanged canonical events. A catalog miss is not a prerequisite to opening a known session. |
| **Saved-history reader** | Serve a bounded `latest`, `before`, `after`, or `around(prompt)` window, and a separate bounded prompt-summary range. Media, expensive tool detail, child detail, and previews resolve separately when needed. The main window includes the readable conversation text, not just placeholders. A permitted saved read does not create a session, subscribe, resume a model, or require live control projection. |
| **Live session state** | Projects current run and recovery status, admitted work, permissions, Stop targets, and notifications. Attach independently of the history request. One ordinary attach per connection and session incarnation; local listeners share it. Retain subscriptions for active or explicitly followed work and unresolved input proofs. Explicit admission readback can still query canonical evidence. |
| **Composer** | Holds the unsent draft and unsubmitted follow-ups for the selected chat or new-draft identity. Uses app-owned catalogs, selected-session settings, and live-control state; does not derive readiness from the visible history page. A submitted attempt belongs to admission/reconciliation, not the editor. |
| **Canonical session/runtime** | Owns persisted settings, execution, workspace policy, input admission, effect evidence, and recovery through the existing owners. Only explicit operations or existing recovery rules run work. Never use the page, index, or a renderer cache to authorize actions, infer permission, or prove delivery. |

**Readiness.** Distinguish first selection in a running gateway from actual cold launch. A saved read does not run the model. Pre-listener MCP and recovery initialization matter only when starting the gateway, not on an ordinary chat switch. Prove the running-gateway path independently. If cold startup still blocks an otherwise authorized read, separate read-ready and execution-ready in the existing gateway after validating the instance, storage namespace and read authentication. Use bounded metadata to identify settled sessions; unresolved sessions still go through canonical recovery. Do not let new input race past recovery/admission fences. If read authority itself is invalid or unavailable, refuse the read and discard any cached view whose read grant was revoked.

**Read authorization is not run permission.** Validate the existing read principal, namespace and session or child identity before returning settled text, summaries or cursors. An unavailable live projection must not block separately authorized text or make a restricted file or child readable. Resolve protected details separately; withhold each detail when its own authorization cannot be established.

**Identity.** Bind windows, locators, prompt summaries, and renderer state to the authenticated gateway/namespace, session identity, and history incarnation or epoch. Addresses are stable display prompt/item IDs, not UI row indexes; use existing replay identities when they are durable and qualify legacy identities within their history epoch. Append and segment rotation do not break locators. Reset/replacement invalidates them; a fork receives its own namespace. Use source generation where it represents replacement, not a mutable revision after every append. Before committing a response, check the selected session and request generation as well. Unknown and stale targets are explicit outcomes, never a jump to a different chat or an implicit latest-page response.

**Wire shape.** Extend the existing thread-read and turn-index operations rather than requiring a new transport. A history window carries bounded rows, an exact target anchor for `around`, both edge cursors, and a current committed history position. Prompt summaries carry stable prompt IDs, order, a bounded label/preview, and an opaque reveal locator; they do not include the turn's full payload. Validate locators, read scope, and range limits again on the server. Support the same semantics through the existing scoped mobile bridge and registry, without requiring extra permissions just to browse prompts. Per the [first-release contract](a3/v1-product-contract.md#selected-first-release-without-legacy-migration), test existing readable development histories; do not require a released-version migration or two-client-version rollout. Unsupported older clients must fail closed rather than infer authority.

**History/live reconciliation.** Attach and history may arrive in either order. Reuse the current attach snapshot and canonical turn/run completion fences to join live updates to committed history by identity. A stale history response cannot erase an active run; a replayed event cannot duplicate a committed row or resolve an unrelated pending send. On a reconnect gap, reconcile live state and the current tail independently of the reader's older window. Keep permission projections out of the settled-page cache.

## 4. How the left rail and viewport work together

1. **Paint first.** Start the latest request at session selection. Use its prompt rows for immediate local markers. After the selected history paints, fetch a bounded page of summary markers at low priority. Load older ranges when the rail or navigator needs them; show that more are available. Do not eagerly drain the index, render one DOM marker per historical turn, or hide a long chat's rail because the current page has few prompts.
2. **Reveal by identity.** Reuse the current viewport's jump/anchor code for an already loaded prompt. Otherwise keep the current view, fetch one window that includes the exact prompt and nearby context on both sides where they exist, mount the target, and then scroll and highlight it. Cancel or ignore the obsolete reveal after another selection, session switch, reset, or delete. A failed reveal leaves the old view in place and offers a retry; it never silently lands on an adjacent prompt.
3. **Keep one reading position.** The history hook owns the selected settled window, edge cursors and pending reveal. The viewport owns the visible range and an anchor consisting of an item ID and offset. Preserve that anchor on prepend, append, refresh and media/layout changes. Distinguish reading history from following the tail; the live overlay does not splice a distant active turn into an old window. Keep the bounded settled-page cache and existing motion controller, not a second history owner or a new global renderer store.
4. **Index prompts, not structural rows.** Include each saved visible user input with its own ID, including multiple visible inputs in one turn where present. A queued/failed local send is not another persisted prompt. Turn-completion strings in message text, compaction, fork markers and delegated activity are not user prompts. Stable IDs key both loaded and unloaded markers. A dense range or an older-index page must still reveal each individual prompt through the existing navigator.

## 5. Composer parity

### 5.1 Design boundary

**Diagnosis.** History and control readback share the wrong boundary: changing permission reads and replays history, while a failed control projection can prevent history from appearing. A smaller page or a faster spinner cannot separate those operations. The editor also conflates typing with readiness to execute and has no draft owner across chat selection. Bulk clearing of queue rows and overwriting a draft during row edit are narrower defects at the existing composer boundary. Keep the established attempt and authorization owners; fix what each operation reads and which input it can change.

### 5.2 Target contract

1. **A stable editor with chat-scoped drafts.** The identified, editable chat and the new-chat draft can be typed into independently of history, catalogs, or execution readiness. Do not remount or disable the editor during a refresh of the same chat. Save and restore text, supported mentions/quotes and ready attachments during a switch; restore focus/caret when returning to the editor, without stealing focus on background updates or opening the mobile keyboard on every switch. Keep the persisted-chat text draft device-local in existing client storage, bounded and keyed by authenticated instance and session incarnation; no sync or new session database. Keep temporary drafts ephemeral. For relaunch, restore attachments only from supported, still-authorized references; otherwise ask to reattach, not silently send without them. Clear or invalidate drafts and references on deletion, replacement, or revoked access. The new-chat handoff transfers the draft only to the chat it created.
2. **Read the right data once.** The existing app settings/workspace owner supplies shared catalogs, selected-session metadata supplies confirmed model/effort/project labels, and live attach or a scoped acknowledgement/readback supplies permission, folder requests, and Stop. Reuse a still-valid snapshot during refresh and reuse mutation results; don't call history for a control change or require a request per field. If exact recovery evidence is needed, it gates that recovery action only. Retain the latest qualified context observation independently of the selected history window; keep the compaction freshness checks, show unavailable when no valid value exists, and update on the next valid observation without scanning older pages. Recent rounds are optional detail, not an open/send dependency.
3. **Keep selection responsive and make it true.** Apply [the session-control contract below](#53-session-controls-model-permission-and-workspace). Changing a setting is not a loading phase for the editor. A valid Stop or Steer uses the current turn's identity and scope, not the model, folder, or mode selected for a later turn; existing live authority fences still apply.
4. **Transfer one draft to one action.** Clear only the submitted/queued version when its owner has taken custody of the full payload (including attachments and context), not on a click, a refused callback or a stale asynchronous completion. Reuse the existing pending-attempt/canonical evidence path. Distinguish held locally, awaiting confirmation, confirmed admission and verified non-admission. A lost acknowledgement leaves an unresolved attempt, not “Failed to send”; resolve it without making another request to execute the prompt. A known refusal retains the payload for explicit retry/edit and does not replace text the user typed meanwhile. A model failure *after* admission is not a delivery failure.
5. **Keep Queue, Steer and Stop distinct.** Compare with Codex in **Queue** mode with matching Enter settings; keep Kohaku's Queue-first default. Plain Enter in an empty editor does not steer; use the explicit row action or reference's deliberate alternate shortcut. Keep the compact, shadow-free queue above and outside the message input, with **Steer** for an active turn and an explicit **Send** when idle. A stale Steer target is a refusal, never a fallback to a new or different active turn. A send or delete acts on its own row; editing a ready row can transfer its payload to the editor only if the separate draft survives. Auto-drain ready rows only after the same chat's verified natural completion and when that next send is admissible. If a setting acknowledgement is still outstanding at completion, keep the row ready and re-evaluate eligibility when it settles without inventing a second run-completion event. Stop (button, shortcut, or existing `/stop` command) fences the stopped work and does not launch a queued follow-up or discard unrelated input. Keep Stop reachable while drafting or while owned background child work remains, and show stopping until settled. The parent remains the only user-control surface for its children.

These changes replace mismatched dependencies rather than add a second composer state machine, a history cache for settings, or a new outbox. Existing workspace/admission, attachment limits and scoped remote access are not UI preferences. Codex-only controls (for example, cloud/worktree modes and service tiers) are not part of the chat-page comparison. Compare supported controls by placement, labels, focus, feedback, and outcomes, not by the number of settings in the two apps.

### 5.3 Session controls: model, permission and workspace

**Kohaku target: change the next turn, not the running one.** Show ordinary model, effort, and next-folder selections immediately and keep the picker and editor usable. A running turn is not a reason to lock the next-folder picker. Persist the choice through its existing owner without a chat reload, model initialization, or separate settings-loading phase. Acknowledgements order the operations behind the scenes; the user can press Send immediately. Show control-local pending or unavailable feedback only when the result really is delayed or unknown. Full confirmation and retirement are real permission transitions, not ordinary preference loading.

**Settings are not transcript data.** Use the app-owned catalogs and session metadata for model, effort, and next-folder choices. The workspace/permission owner supplies the effective mode, grants, and relevant recovery state through the existing attach or mutation result, with a scoped read if confirmation is missing. Neither reading nor changing a setting uses the WebUI transcript, even while that legacy store remains readable. A historical approval row is not current authority.

| Control and owner | Target behavior |
| --- | --- |
| **Model + effort · session model owner** | On a new draft choose the pair without a run, and bind it to the existing first-send handoff. For a saved chat reuse the same model owner via a typed, chat-scoped result on the existing mutation transport; keep `/model` for its user-facing use. A chat change must not rewrite the app default or another chat. Do not fetch the catalog again or start inference just to change the choice. Distinguish the next-turn choice from the running turn's model, and admit the next input only under the confirmed pair. |
| **Sandbox/Full · permission owner** | Use the authorized projection or a scoped read, and settle the picker from the mutation result. Full still requires confirmation and eligibility. If supported during a Restricted turn, confirmed Full applies to the **next request**; it never widens the running turn. Returning to Sandbox keeps the existing Full retirement fence; show **Retiring** if cleanup is still outstanding, not a falsely settled mode. Preserve source/revision, native supervisor, exact **Once** grant, and paired-owner checks. |
| **Working folder · workspace scope owner** | In a draft, select from the authorized catalog and bind the folder at creation. In a saved chat, record the next folder through the same scope owner with a correlated result, including while a turn is active or an earlier send is being reconciled. A new turn uses that folder only after the server verifies the scope and mode together. An unavailable or forbidden folder is still rejected; a selection is not a grant. Never retarget active work or transfer its grants to the new folder. |

**Why not remove the current lock as-is?** The current write changes effective `workspace_scope` and can invalidate a live folder recovery request. [Steer compares the derived scope to the captured turn scope][kohaku-scope-steer]. Replacing the scope with folder B while folder A is running can reject a valid Steer for A or disturb its recovery state. Separate the **next-turn preference** from the **already admitted scope** at the existing workspace/admission owners before removing the blanket UI lock. Only a new-turn admission consumes the next settings. Stop, Steer, recovery, and child work continue to resolve the admitted turn and recheck its live authority. Keep safeguards against mutating an active scope in place. The [last-admitted request defaults][kohaku-admitted-defaults] are not a pending-choice slot; later writes from turn A must not overwrite a newer preference for B.

**Ordering and failure.** Capture the selected settings at submission and order the new-turn admission against any earlier in-flight change it depends on, without a routine settings preflight or readback. A later picker edit or stale receipt cannot alter already submitted work. Consume results only for the matching chat incarnation and setting operation/revision. A rejected choice preserves the draft, restores the confirmed display and explains the failure; do not silently send under the old choice or repeat a privilege increase after a lost receipt. First Send and automatic queue drain use the same rules as ordinary Send. A next-folder choice does not clear the current turn's recovery request. At a new admission, recheck grants and confirmation against the actual new binding; do not carry a **Once** grant forward. No new settings service, separate composer loader, or change to child behavior is required.

**Keep real work separate from extra work.** Eliminate model-catalog duplication and control-only transcript requests first. The current [canonical metadata writer][kohaku-metadata-writer] also reads and rewrites source records under a lock. That is distinct from the unnecessary display-history readback; moving the mutation off the event loop doesn't remove its work. Routine settings reads and writes must be bounded independently of settled history length. Resolve that at the existing storage owner under gate G3; do not hide unbounded persistence behind an optimistic label or change authority to make settings feel fast.

## 6. Persisted history and bounded reads

**Selected design:** keep the existing durable files initially. Make the segment/turn projection seekable using **one rebuildable read index**: a small session head (identity, committed coverage, latest window locator) and a paged directory of prompt summaries and turn/record locations in the existing active file and immutable segments. Use the existing manifests and writer/rotation boundaries where possible. Look up a bounded index range and read the indexed byte ranges; do not load or parse the entire index on each request. Index rows point at original records; they do not copy full turns or own session data. No new database, renderer rewrite, or server memory cache is required by the design.

- Publish index coverage only after the corresponding durable records commit. Bind it to that incarnation and the source/segment revision it describes. An interrupted update may leave the projection behind; it must never expose uncommitted rows or make stale offsets valid. Catch up or rebuild from durable facts without rewriting them. Bound the index and history work independently of older settled turns; a large tool output or media item can show a bounded, explicit summary and load detail on demand rather than delaying all text. Use structural event parsing, not substring marker checks.
- Separate stable prompt identity from physical read locations. The current [canonical append path][kohaku-source-append] commits a complete replacement, and a metadata edit can shift event offsets even when no prompt changed. Prove a valid mapping against the actual committed file or segment generation before using a range. Do not invalidate public cursors or rebuild the entire index on every ordinary append or settings change.
- Read only the metadata needed for current authorization and identity through a validated server-owned path. The browse index is not permission evidence, and full source validation still applies to execution. Keep slow legacy repair, projection rebuild and bulky disk reads off the ordinary request/event-loop path. For a pre-index history, try a bounded authenticated tail read and index older segments out of band. If a legacy record cannot safely fit that fallback, still keep it readable via explicit targeted recovery/detail loading and identify the partial result; never return an empty chat or silently discard evidence. Verify the **existing-chat first open with no index**, not just newly created chats. Do not ship if ordinary legacy opens still fall back to a long synchronous scan.
- **Final durable ownership:** retire the second full WebUI transcript write for the new format once the cutover checks pass. The canonical session remains the source of model/execution history. Store common facts once, and persist only distinct, permitted display facts under the same session lifecycle and stable IDs when they cannot be reconstructed from other owners. The chat UI still renders a rebuildable projection of those facts; current settings and authority do not come from it. Do not store raw reasoning, private tool payloads, or model context in the GUI projection. During cutover the old transcript remains readable as history for old chats. No mandatory bulk migration or deletion.

Before retiring any writer, record field-by-field provenance: canonical prompt and answer, bounded tool/approval outcome and file-edit display, permitted reasoning detail, context-compaction markers and budget display, fork and parent/child lineage, incomplete tails and recoverability, attachment/generated-asset references, and retention/deletion. Distinguish legitimate display-only facts from repeat copies. The [existing storage note][storage-note] reports size, not equivalence. A source-only fixture already lost recorded display detail. The [public Codex local writer](https://github.com/openai/codex/blob/922510f4d7570b42838e015787ed53abfa8761a1/codex-rs/thread-store/src/local/live_writer.rs#L327-L364) is evidence for durable facts plus a rebuildable index, not a reason to adopt SQLite or remove required facts. Start the provenance work with the read design; cut over new writes only after parity and restart/crash proof.

## 7. Work-plan handoff

**Ready to plan, not ready to dispatch.** The design decides what users see, who owns settings and authority, what a history read returns, and which data must survive. It does not yet choose physical index offsets, the bounded metadata-write mechanism, or which existing reader dependencies can retire. Carry those as explicit gates, not as assumptions for an implementation worker. Design gates can be settled by tracing the reviewed code and using isolated fixtures; passing the candidate checks in §8 is a separate step.

## 8. Release checks

- **Cold work:** Use short and 10×-long histories with the same recent turns, including a segmented fixture and a pre-index fixture. Count canonical events, parsed records, bytes/ranges and requests. The latest and direct-jump path reads bounded index pages and selected records, not the whole source, transcript, or prompt index. The catalog and settled startup discovery do not replay old turns. Withhold sidebar, permission, Stop and other live replies; release the latest history only and assert the actual chat text paints, while unauthorized data and actions are still refused. Exercise blocked MCP/recovery separately on true gateway startup.
- **Real reveal:** From the latest window, choose an old prompt not loaded or mounted and verify its exact visible anchor and highlight. Page backward and forward without gaps/duplicates; go to latest during a run. Include multiple user prompts in one turn, a literal `turn_end` message, a short latest window in a long chat, and a history beyond the first summary range. Reject late results from an old selection or rapid second jump.
- **Continuity and authority:** Preserve the anchor on warm revisit and refresh. Reconnect with live work or one uncertain send while reading old history. Check canonical once-only admission, Stop, unavailable controls, and no scroll steal. Replace/delete and recreate a chat; old windows, permissions, cursors, and media must no longer be usable. A fork must resolve only its own lineage.
- **Settings isolation:** Withhold or fail the display-history reader while the settings owner is available. Hydrate and change model, effort, next folder, and permitted mode without touching the transcript. Count routine metadata reads and writes separately on short and long histories; neither should scale with older settled turns. Test real confirmation and retirement separately.
- **Durability:** Delete/rebuild the read index, interrupt publication/rotation, restart, compact, and compare the same prompts and supported detail. Preserve unfinished-turn status, attachment access and retention, child boundaries and fork markers. Run the storage parity checks before any write cutover and exercise existing pre-index files on the candidate.

## 9. Audit evidence

These observations explain the selected design. They describe the reviewed baseline, not a passing candidate or native parity proof.

### 9.1 Compared workflows

The reference is the installed **ChatGPT Codex Desktop build `26.1111.71704`** for a normal local chat, not the CLI, the mobile Codex UI, or an assumption that every feature flag behaves the same. The comparison uses read-only inspection of its packaged renderer, the [Desktop entries in the changelog](https://learn.chatgpt.com/docs/changelog) and the [App Server turn contract](https://learn.chatgpt.com/docs/app-server#turns). These establish the design and specific behavior; the side-by-side native interaction check in §8 is still open.

| Workflow | Codex Desktop reference | Kohaku at the reviewed revision |
| --- | --- | --- |
| **First open, revisit, and focus** | Conversation passes history loading, resume, and submit-disabled separately. The adapter can block submission for a concrete reason without making transcript loading the editor state. | **Partial match.** A known chat can start its history read before the list returns, but opening without a resolved session can disable the editor. A slow effort update disables the entire composer, including otherwise enabled Stop. Keep the editor steady; gate operations, not the draft. |
| **Unsent draft and attachments** | Desktop `26.818` records preserving formatting and mentions when switching chats; this build has scoped prompt draft save/restore. Focus is a separate decision. | **Model, effort, permissions, and workspace** | Selection, server-confirmed settings, and the active turn's execution state are distinct. ### 9.2 Session-control reference

**What the Codex Desktop reference actually does.** This is the inspected local-chat path in `26.1111.71704`, not a claim about every version, host, or managed policy.

- **Model and effort.** The app distinguishes draft/default settings from an existing conversation's model and effort. For that conversation, the picker applies the pair through its next-turn settings owner. The renderer serializes `thread/settings/update` per thread where supported and the start path awaits that thread's pending update. The picker can show a control-local loading/unavailable state. This is not a chat-history refresh or a provider inference request. The documented [`model/list`](https://learn.chatgpt.com/docs/app-server#list-models-modellist) populates the catalog; [`turn/start`](https://learn.chatgpt.com/docs/app-server#start-a-turn) can carry overrides, and [`turn/steer`](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn) does not accept model or workspace overrides.
- **Permission mode.** The [desktop permissions picker](https://learn.chatgpt.com/docs/permission-modes#choose-a-mode) is beneath the composer and reflects the selected chat. Its renderer resolves the selected mode against configuration and workspace roots, confirms Full access, and reports failed updates. Sandbox scope and approval reviewer are separate; a supported active-turn update in the inspected code changes the **reviewer**, not the sandbox or execution root. The presence of that path is not evidence of in-flight privilege expansion. Do not add Codex-only Auto-review/custom policy modes or copy its sandbox implementation.
- **Workspace.** A [local project](https://learn.chatgpt.com/docs/projects#work-in-a-project) associates chats with folders on the execution host. The inspected new-chat path resolves its project and roots into a working directory; the local follow-up path reads the existing conversation's working directory. The App Server can accept `cwd` for a **new** turn, but that is not proof that the desktop picker can relocate a running chat. Compare project picking and display in the native pass. Do not treat sidebar project organization, git worktree handoff, or selecting a folder as permission to use it.

| Control | Kohaku baseline |
| --- | --- |
| **Model + effort · session model owner** | [The model picker][kohaku-model] launches `/model` and ignores rejection; effort waits but disables the editor. [App][kohaku-settings] and the shell both read settings. The model owner already [validates and commits the preset/effort pair][kohaku-model-owner]; [a textual command reply][kohaku-model-command] is not a success receipt. |
| **Sandbox/Full · permission owner** | [`prepare-full` / `workspace.access.mode.set`][kohaku-mode-api] already have typed results. [The shell][kohaku-mode] applies the acknowledged mode but still waits for the folder-request history read. The two [fallback control reads][kohaku-readback] call history with `limit: 1`: on 24 vs. 240 turns the response had two rows both times but read 48 vs. 480 canonical events and decoded 72 vs. 720 transcript rows. |
| **Working folder · workspace scope owner** | [The app][kohaku-folder] shows a provisional scope and sends `set_workspace_scope`; the server validates and stages/persists it, then sends a [general metadata event][kohaku-scope-server], not a result correlated to that selection. The current operation changes the saved scope and [rejects a running chat][kohaku-scope-owner]. |

- Reference renderer assets in `ChatGPT.app/Contents/Resources/app.asar`: `734847.744513d859.js` and `283497.c96e5fb6d4.js` (history/resume/submit), `486887.d08998ca6f.js` (editor, contextual controls and Queue/Steer), `79584.9737da4dbb.js` (model/effort), `907538.0c31293919.js` (scoped prompt draft storage, turn requests, unknown delivery and latest usage). - An additional focused `thread-composer` run passed 4 cases on that pin, including the existing second-Enter and manual `/stop` cases. - Session-control reference evidence: `415411.7ac07a1d91.js` (next-turn model/effort), `143529.9093ac3f21.js` (permission picker and Full confirmation), `907538.0c31293919.js` (settings ordering, run start and existing working directory), and `486887.d08998ca6f.js` (new-chat project/roots). - On the pinned Kohaku export, 11 focused pytest cases passed across `test_model_command.py`, `test_permission_v2_api.py`, and `test_websocket_channel.py`. They cover rejected/persisted/session-local model settings, attach's canonical model, the current ban on replacing scope during a run, deferred Full and rollback, source-bound confirmation, and retirement.
