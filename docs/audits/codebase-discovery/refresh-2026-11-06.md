## Connected current behavior

### Turn execution and ordinary tool-error recovery

`AgentLoop` and foreground delegation enable fail-on-tool-error; execution stops the
failing batch and records later calls as skipped
([execution.py:169](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/tools/execution.py#L169)). Runner records tool
results/checkpoints before clearing an eligible terminal and adding recovery guidance
([runner.py:1001](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/runner.py#L1001), `:1039`, `:1083`). The next model
round chooses new work. Default generic allowance is two recoveries per run and requires
another iteration. Signatures include tool names/arguments and terminal content, exclude
call IDs, and suppress repeat recovery (`runner.py:150`, `:228`).

Non-null `_prepare_error_kind`, SSRF/workspace markers, policy metadata, unavailable-tool
text, repeated signatures and `dream:` sessions exclude this generic path (`runner.py:959`).
Missing-skill, context-repository exec and trusted pre-dispatch recovery remain separate
(`:931`). Registry argument-shape/schema failures return unclassified `ToolResult.error`
([registry.py:282](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/tools/registry.py#L282)); thus not every preparation
failure is excluded. Guidance enters the runtime transcript ledger (`runner.py:357`).
How classification, variable error text, mixed/skipped batches and Dream exclusion align
with intended behavior remains a later comparison topic.

The shared coordination/source split is unchanged: composition owns the graph and writer
lease; admitted turns bind execution/source authority; the runner owns model/tool work;
queued outbound completion is separate from network receipt. Retained goal/self factories
and goal state do not override explicit manifest absence. Canonical source command
handling admits `/new`, `/help`, `/model`, `/history`, `/status` and trusted shell while
`/goal`, `/trigger`, `/dream` receive migration-unavailable
([loop.py:4336](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/loop.py#L4336)).

[RuntimeComposition](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/runtime_composition.py#L310) creates a definitions-only

preserves occurrence/run identity with fresh history
([canonical_execution.py:35](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/cron/canonical_execution.py#L35)). Silent cron
strips message tooling, ordinary publication and implicit approval (`loop.py:3789`, `:3826`).

[Composition](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/cron/composition.py#L134) consumes its execution fence,
executes/verifies/applies quota handling and commits completion. Success requires exact

([canonical_result.py:24](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/cron/canonical_result.py#L24)). Outbox preparation
precedes visible linking and dispatch (`composition.py:193`, `:208`). Durable sending
authority precedes channel invocation
([delivery_runtime.py:947](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/cron/delivery_runtime.py#L947)); receipt checks
bind channel/target/action/digest/message count
([channel_sender.py:47](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/cron/channel_sender.py#L47)). Exceptions, cancellation

### Transcript projection and canonical completion fences

HTTP hydration supplies the session loader and actual WebSocket active-turn state
(`ws_http.py:1483`). Without a supplied active turn, the builder can repair an unfinished
selected tail (`transcript.py:2821`). Exactly one user and a candidate containing assistant
records are required; matching uses text, media paths, CLI apps, MCP presets and session
mentions, preferring the newest matching candidate or otherwise a unique match (`:1368`,
`:1502`). It replaces partial answers, preserves trace/reasoning/edit rows and display
turn ID, stamps current wall time and synthesizes completed outcome (`:1510`).

This alters the response, not display-log persistence (`:2840`). `completed_turn_ids`
can include this synthesized completion despite its explicitly-persisted-completion
docstring (`:2777`); grouping visible user/assistant records does not itself verify
canonical terminal outcome (`:1192`). `WebuiSessionAccess._messages` supplies no active-turn
state to the same builder ([session_access.py:120](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/webui/session_access.py#L120)).
The persistence invariant that makes those assistant records sufficient, repeated prompts,
pagination and session-reference reads remain unknown at this discovery depth.

Frontend reconciliation was not replaced. It prefers server `has_pending_tool_calls`,
reads latest-page lifecycle fields, and prevents older pages replacing that lifecycle
(`useSessions.ts:119`, `:484`, `:774`). Thread refresh gates history version, run generation,
lineage, UI revision and durable baseline (`ThreadShell.tsx:1682`, `:1885`) before accepting
and clearing local stream state (`:1500`, `:1634`, `:1675`). Client completion fences prune
late frames/settle represented sends (`nanobot-client.ts:534`); canonical completion also
releases keepalive (`:593`). Synthesized display completion must remain distinguished
from source terminal proof and from delivery acknowledgement.
