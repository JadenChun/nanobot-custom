The connected recovery flow begins with admission, not reconciliation. `runtime_preflight` ([runtime_composition.py:183](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/runtime_composition.py#L183)), `AgentLoop` ([loop.py:594](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/loop.py#L594)), `MemoryStore` ([memory.py:100](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/memory.py#L100)), and `JsonlSessionStore` (`manager.py:980`) call startup admission. Clean absence returns without recovery publication. Retained quarantine state must be complete, committed, and sealed; historical validation then uses an existing workspace gate and frozen evidence. Bounded constructor mutation separately reinspects under its gate. Existing-evidence verification can fsync files/directories, so its read-only property concerns publication/repair rather than absence of durability syscalls.

Explicit receipt recovery follows this source sequence:

`CAPTURED → CONVERSION_PREPARED → JSONL_APPLIED → CURSORS_APPLIED → LEGACY_FINALIZED → conversion COMPLETE → transaction PREPARED → HISTORY_APPLIED → MEMORY_APPLIED → OFFSET_APPLIED → RECEIPT_COMMITTED → transaction COMPLETE`.

`reconcile_pending_memory_receipt_offline` ([memory_recovery_coordinator.py:99](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/memory_recovery_coordinator.py#L99)) dispatches those stages and releases inspection leases before each stage acquires its own locks. It leaves the pending receipt present. Each transaction stage acquires workspace authority before checked-session locks; checked recovery issuance validates the live operation and candidate namespace ([checked_source.py:1753](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/session/checked_source.py#L1753)). Offset replacement uses a fresh replacement authority and then a fresh reader to classify the result.

Receipt finalization has a separate lifetime. It holds existing workspace authority and the checked session, prepares and copies the original receipt, verifies unchanged receipt bytes/stat before unlink, establishes durable absence, reopens the copy-ready evidence, reproves terminal semantics, and publishes the sealed commit. An interrupted post-unlink operation can resume only through the explicitly named copy-ready replay API. On later startup, historical seal reconstruction uses the retained receipt and frozen transaction/conversion outputs, allowing ordinary live state to have advanced since finalization.

The session writer lifetime is also distinct from a recovery operation. `RuntimeComposition.define` selects `DurableSessionAuthority` by default ([runtime_composition.py:412](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/runtime_composition.py#L412)); graph acquisition acquires its lease and retains its close callback (`:491`). That authority holds `LifetimeWriterLease`, constructs a managed manager, and composes registered modes. Closing releases resolver resources and revokes namespace access. `OfflineSessionOperator` uses the same lease mechanism with explicit copied-state/operator admission.

Artifact projection belongs to admitted live source turns when configured: artifacts default disabled ([config/schema.py:932](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/config/schema.py#L932)); `AgentLoop.from_config` constructs the factory only when enabled ([loop.py:896](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/loop.py#L896)); runner admission requires an allowed reader, source writer, and exact read-file tool ([runner.py:581](https://github.com/JadenChun/nanobot-custom/blob/27adced0aacd55d61791bb88a7240d7ad7bd5b75/nanobot/agent/runner.py#L581)).
