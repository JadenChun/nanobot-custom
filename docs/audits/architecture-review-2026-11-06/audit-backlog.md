# Bounded audit backlog and dependency map

The REF1–REF6 mechanism comparison is a targeted checkpoint. Whole-project discovery is
complete at module/relevant-body depth; detailed semantic audits remain queued across all
eighteen streams. A candidate below is not an accepted repair or an assertion that a whole
stream has been audited. Sandbox remains the first later audit priority.

Each future source package freezes the same pins or records an explicit delta, reads the
applicable guidance, owns **only its assigned report/provenance**, and returns concrete
requirement/trigger/caller/writer/identity/lifetime/authority/error/compatibility evidence,
uncertainty and smallest correction. Git blob/hash/link processing is the validation
boundary. No application imports, scripts, tests, builds, checkers, services or benchmarks
belong to these source-audit contracts. Later code repairs require separate contracts and
branches, including their own focused tests and repository/P6 obligations when applicable.

Disjoint reads and disjoint implementation files can still share a schema, lease, authority
or lifecycle. Land/accept common contracts before dependent repairs; integrate in dependency
order and re-review combined callers. A conflict-free merge does not prove semantic agreement.
Staging changes require a named differential checkpoint and affected caller reinspection;
never refresh hashes silently or reopen the full discovery inventory by default.
