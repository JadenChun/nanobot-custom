## Cross-layer evidence and precise exclusions

### A. File/tool/child confinement — where source truth diverges

[S01-F01](../reports/S01.md) is **not** a file-tool bypass. At frozen nanobot/session/workspace_focus.py:150–210, Full/task effective-access shortcuts report read/write based on directory presence and permission state; nanobot/context_repo/policy.py:178–270 validates target/context restrictions first. The WebUI may show an eligible command/path that enforcing file tools reject. Minimal option: one typed eligibility decision consumed by focus and file tools, retaining actual file existence and native backend readiness as distinct facts.

[K01-F01](../reports/K01.md) concerns prompt/source inputs and symlinks not always passing the same ResourceAccessPolicy. [T01-F07](../reports/T01.md) concerns browser/device cwd and output destinations. They are real *admission gaps* under their stated managed/full-host conditions, and must not be downgraded because a WebUI projection is merely misleading.

[X01-F01](../reports/X01.md) is the clearest different plane: nanobot/agent/tools/cli_apps.py:136–160 passes the turn's workspace but nanobot/apps/cli/service.py:1431–1476 calls subprocess.run with model-supplied args after cwd selection. Cwd validation and filtered environment do **not** constrain the spawned host program's full filesystem and network effects. Compare nanobot/agent/tools/shell.py:525–565, where native command preparation and reservation are explicit; the shell itself still has separate sandbox and process proof limitations. Restrict/disable unconfined CLI-app execution for managed/restricted turns **unless** a real approved execution owner is available. Do not substitute argv regex for an OS sandbox.

[K01-F03](../reports/K01.md) is malformed high-precedence skill discovery before creator/package validator, unchanged in staging. [K01-STG-F01](../reports/K01.md) is **separate**: staging summary labels a bundled skill under relative skills/name/SKILL.md, but frozen and current ReadFileTool first resolves that exact path in the selected project and uses the actual bundled fallback only if the project path is missing. Source-proven *provenance mismatch*, not automatically a private-path breach. Resolve builtin identity unambiguously for non-agent selected project and test actual file returned.

### B. Grant/approval and effect classification — no trust laundering

[T01-F08](../reports/T01.md) global desktop input is enabled through a different surface from main browser/device risky-action approval; [K01-F06](../reports/K01.md) nested Codex --yolo advice delegates a sandbox/approval bypass not captured by the outer native tool's risk descriptor. A repair owner must distinguish direct OS desktop effects versus an external nested agent gaining independent tool authority. User enablement might be blanket consent only if explicitly accepted at D2; a status flag is not evidence of approval for an arbitrary future operation.

At frozen nanobot/agent/tools/mcp.py:669–690, a remote readOnlyHint is returned as authority **before** checking whether the MCP transport/server is trusted. Even the local “trusted_for_heuristics” predicate only checks stdio or loopback origin, which is not proof that an arbitrary server operation is read-only. [T01-F04](../reports/T01.md) therefore stays independent of [X01-F02](../reports/X01.md): nanobot/crawler/worker.py:788–796 emits element.click() under read-only “expand,” a direct effect-classification mismatch despite explicit click being denied. Both require source/operation-specific read-only policy, not a blanket all-delegates-disabled change.

[S02-F02](../reports/S02.md) is a process-admission life-cycle fact: frozen shell.py:525–565 reserves native admission before a second approved input revalidation may return; correcting it requires cancelling only proven **unlaunched** reservations, not relaxing the revalidation or falsely declaring launched work complete. [S01-F03](../reports/S01.md) duplicate owner-epoch native counts are conservative accounting, not demonstrated wider authority. Keep both in the later I02 state/lifetime pass, but do not mistake them for duplicate P1 risks.

### C. Request entrypoints, application scopes and browser-worker transport

At frozen nanobot/remote/edge.py:255–279 the mobile gateway validates the bearer token and revalidates current revocation/expiry; its HTTP read handlers additionally pass chat.read to _authorized_delivery. At nanobot/remote/edge.py:609–669, the explicitly mobile frame handler checks attachment.write, chat.write and logout scopes. In contrast, the shared typed WebUI command router at nanobot/webui/inbound_commands.py:591–661 revalidates mobile identity but branches into new_chat, attach, hydrate and typed commands without an equivalent command-specific chat.read gate. [R01-F02](../reports/R01.md) therefore is **not missing login**; it is missing command-level scope application to the **mobile typed WebSocket path** after authentication. Default owner pairing's broad scopes mask the trigger; narrowed valid owner scopes expose it. A small action→scope check in the shared command admission, supplied by the remote edge owner, is smaller and safer than duplicating business dispatch or relying on the frontend.

[E02-F02](../reports/E02.md) concerns optional non-loopback WebUI listener configuration that can be started without effective auth (defaults are loopback and token-required); frozen nanobot/webui/gateway_endpoint.py:98–125 shows token/trusted proxy/issued-token conditions and the allow path when websocket_requires_token is false. [E02-F22](../reports/E02.md) is a separate local side-effectful notification GET lacking mutation-token/origin authentication. Loopback+Host is not a general cross-origin mutation authorization. These cases do **not** collapse into R01-F02 and no claim of current default public exposure is made.

[Q01-F01](../reports/Q01.md) is distinct again: an explicitly enabled Windows Edge profile worker uses loopback TCP without per-caller authentication; local untrusted processes can submit worker JSON operations. Linux Unix socket permission/service isolation is a positive counterexample and should remain. Browser service read-only action classification (X01-F02) must be enforced independently of authenticating the socket.

### D. Instance roots and information trust exits

[C00-F06](../reports/C00.md) documents captured custom Config/media network roots diverging from global helpers. [E02-F11/F13/F15/F16/F17/F18](../reports/E02.md) identify distinct CLI-app/MCP/grant/OAuth/remote-owner/usage root families. Those are **related by an instance-identity input**, not one database, key or permission boundary. A minimal composition-owned instance-roots bundle should be frozen once and passed through existing individual constructors. Custom gateway root A must not silently consult B's grant credentials or remote owner, and file/prompt/network policy must not inherit stale global state. Compatibility/home-wide accounts require explicit D2/D4 choice; changing them all to per-instance secrets without migration would break known OAuth flows.

[K01-F08](../reports/K01.md) routes optional video semantics directly through a separate OpenAI key/model in conditions described by the original finding, bypassing the configured provider/policy owner. [Q01-F02](../reports/Q01.md) prints unredacted audit argv and Git remote userinfo despite masking selected JSON config values; [R01-F11](../reports/R01.md) logs signed media URLs which are bearer capabilities; [X01-F04](../reports/X01.md) blends cross-origin CLI app registry install metadata while keeping a higher-trust source label. They imply four individual remedies: host-provided semantic model callback; allowlist/redact audit diagnostic fields; never log signed media capabilities; source-qualified install executable metadata. None implies a secret was captured, a malicious package was installed, or a provider call was performed in this audit.

Finally [K01-F12](../reports/K01.md) and [K01-F13](../reports/K01.md) have high instruction-integrity consequence but very different lifetimes: raw low-trust transcript replay into system prompt versus Dream writing skills beyond the set it audits/restores. Treat as separate repairs and retain failed-compaction and skill-only Dream cursor tests in I02. No new authority tier or prompt protocol is chosen in I01.

## Integration decisions *not yet made* and proposed acceptance probes

The following are **repair-package candidates**, not implementation approval:

1. **Policy/permission facts contract (I01-A, D2/D4):** select effective current request+grant+source proof once for eligibility. Ensure focused UI, file tools, prompt reads, browser/device output and actual shell/CLI process owner each enforce their proper plane. Contract test: same protected repo and full/once grant yields consistent **admitted versus displayed** facts; CLI app under restricted turn is confined or rejected.
2. **Delegation/risky effects (I01-B/C, D2/D3/D4):** require trusted remote MCP tool classification before delegated execution, no clickable “read-only” crawler action, consistent desktop input approval and nested-agent bypass policy. Use effect-shaped regression cases and explicit trusted/untrusted origin matrix.
3. **Remote listener/WS/worker (I01-D/E, D1/D2):** test non-loopback listener with no effective token, reduced-scope valid owner mobile WS hydrate/read, cross-origin loopback notification GET, and Windows authenticated worker from a non-agent local process. Test Linux socket ACL and default loopback+token positive paths separately; no assumptions about remote attacker reachability.
4. **Instance roots and exfiltration (I01-F/G, D2/D4/D7):** two explicitly different gateway config roots, grant/private/remote/OAuth/media/usage stores and source-bound signed-capability logging. Preserve deliberately global auth profiles only by explicit compatibility policy and scoped migration.
5. **Instruction integrity (I01-A/H, D2/D4/D7):** malformed higher-priority skill versus valid builtin, selected project same-name path collision, degraded compaction text role and Dream skill-only edit/restore. Do not solve prompt-source ambiguity by broadening file permissions.

**No test was executed**. Conditions above specify future deterministic acceptance, not evidence of completed passing coverage. More urgent security repair might precede easy P01 UI cleanup if the relevant managed or remote modes are in the supported product threat model; the audit does not automatically select a severity escalation without user policy decisions.
