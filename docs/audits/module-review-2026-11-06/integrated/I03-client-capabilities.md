## I03-A — Queued content must survive until local send admission; preserve modality and FIFO

[U01-F01](../reports/U01.md) is a queue eligibility bug, **not attachment loss**. At frozen `webui/src/components/thread/ThreadComposer.tsx:499–536`, restored queued prompts legitimately include images without text; manual `sendQueuedPrompt:1961–1992` sends text **or** queued images. However automatic `sendNextQueuedPrompt:1997–2034` finds the first item only when `prompt.text.trim()` is nonempty. The end-of-stream effect `:2036–2048` invokes that function, potentially leaving an earlier attachment-only item behind and sending later text out of FIFO order. The smallest correction is **one sendability predicate** (nonempty text OR valid attachments) shared by manual/auto paths and first eligible FIFO ordering. Keep held/send-snapshot/reconnect/unknown-send semantics; do not blindly resend an ambiguous ordinary message.

[D01-F01](../reports/D01.md) is instead *dequeue ownership*. Frozen `tui/src/app.ts:1576–1583` calls `promptQueue.takeFollowUp()` then `sendPrompt`; `tui/src/app.ts:1016–1025` catches `client.send` errors and marks unsent status but does not reinstate the already dequeued prompt. The direct composer path has separate draft-preservation behavior. Commit dequeue **only after local transport admission** or restore the exact queued item on failed admission. Neither U01 nor D01 needs a universal queue implementation or an “exactly once over network” claim.

**Deterministic future checks:** attachment-only then text under streaming→idle; queue respects held IDs and no skipped earlier row; manual and automatic same criterion; TUI local send throws after peek and queue remains; session switch/failed connection retains input. No such tests ran.

## I03-B — Reused client surfaces need a request selection/generation commit fence

[U01-F02](../reports/U01.md): frozen `webui/src/hooks/useSessionGeneratedAssets.ts:28–86` cancels the initial fetch on `sessionKey` change, but `loadMore` captures a cursor then unconditionally `setGroups(current => [...current,...payload.groups])` after an awaited fetch, **without an equivalent cancellation/generation check**. Switching A→B while A pagination is pending can insert A's page in B's sheet. This is a same-user, same-client **display/state integrity** issue, not a cross-account data disclosure finding.

[U01-F03](../reports/U01.md): frozen `webui/src/components/settings/channels/ChannelSetupPanel.tsx:280–320,349–400` resets state when `feature.name` changes, but `saveCredentialSettings` and `checkCurrentSettings` await validation/configuration and then set validation/notice/saving regardless of whether the displayed feature changed. A save request still targets the captured A channel; **do not claim it mutates B's backend config**.

[U01-F04](../reports/U01.md): frozen `webui/src/components/settings/SkillsCatalogSettings.tsx:339–432` cancels the detail fetch when the skill changes but leaves skill `toggleEnabled`/delete callbacks free to write detail/busy/close after a later skill is selected. Underlying mutation keeps the captured `activeSkill.name`; this is a **wrong-sheet completion** risk, not demonstrated cross-skill backend mutation.

[D01-F02](../reports/D01.md): frozen `tui/src/app.ts:2727–2754` reads `this.client.activeChatId` for `/context` but then updates title/tokens/context panel on completion with no snapshot/identity check. Neighboring `refreshSessionMetadata:2758–2775` uses `requestId` and chat identity, `refreshContextEstimate:2780–2792` checks the chat. Reuse these existing request-generation/chat fences, including stale success/error/finally paths; do not adopt a generic cross-platform state manager.

**Deterministic future checks:** delayed A pagination then B selection/reset; channel A validation and B opening; skill A enable/delete then B opening; TUI A /context then B and a late error; ensure stale `finally` cannot clear B busy state. Preserve authorized server target and current API contracts.

## I03-C — Local optimistic states and turn-local completion projections require truthful boundaries

[U01-F05](../reports/U01.md) at frozen `webui/src/hooks/useSidebarState.ts:181–217` clears pending before the request, and on failure requeues the snapshot only if nothing newer is queued; it neither retries while the socket stays open nor rolls back/flags unsaved state. Existing on-status OPEN retry only fires on a future status transition. Model **pending / sending / committed / retryable or terminal unsaved** with bounded retry and visible reconciliation. This shares I02's applied-vs-ack distinction but is **not** a second E02-F20 backend mutation finding: the sidebar actor owns UI preference persistence and the server remains authoritative.

[U01-F06](../reports/U01.md) at frozen `webui/src/lib/thread-event-projection.ts:122–143` scans backward for an assistant with absent/matching turnId but does not stop at a current user turn boundary. A terminal event for an empty assistant response can stamp an older legacy assistant's usage/latency/completion. Stop at the active user/turn boundary before applying compatibility. No server payload or durable source corruption was shown.

## I03-D — Manifest, slash commands, skill guidance and active consumers must align

The explicit active core manifest is `nanobot/agent/tools/fork_factories.py:1–112` and registration is `nanobot/agent/tools/loader.py:203–219`. It intentionally imports/constructs tools explicitly; **mere presence of a source class is not registration**. It registers `read_file`, `write_file`, `edit_file`, `list_dir`, `exec`, web tools, `cron` and other explicitly selected tools, but **not** `find_files`, `grep` or `apply_patch`. Shipped `nanobot/templates/agent/tool_contract.md:21–22,50–66` explicitly instructs their use. [T01-F10](../reports/T01.md) is the underlying `apply_patch` omission, while [K01-F11](../reports/K01.md) is **broader live guidance-versus-manifest drift** including missing find/grep. **Avoid falsely closing K01-F11 by adding apply_patch alone**. A small available-tool fact/manifest-derived guidance, or a consciously restored capability and tests, is sufficient. Do not import every dormant tool for parity.

The command router at `nanobot/command/builtin.py:1116–1141` registers `/goal` and `/trigger`. `/goal` `:942–980` sets metadata + permission scope, but default core construction does **not** register both goal mutation tools; durable active-goal state cannot be established in that default path ([A01-F02](../reports/A01.md)). `/trigger` `:1017–` and `nanobot/cli/commands.py:505–532` create/queue local-trigger records, but default `nanobot/cli/gateway_runtime.py:490–689` starts cron and process completion conditionally **without starting a local-trigger queue consumer** ([A01-F07](../reports/A01.md)). It is a **shipped dormant/activation mismatch**, not proof that default local trigger replay or approval abuse is active. [A01-F08/F09](../reports/A01.md) remain **conditional activation blockers**: no silent consumer enablement without canonical delivery identity, no automation authorization to settle risky-action approval.

**Smallest decision deferred to D4:** either activate each feature **with** required tools/runtime/authorization/correct recovery and tests, or conditionally remove its command/prompt promise from shipped discovery. Do not report “completed goal/trigger” based only on parsing a command or storing a request.

## I03-F — Versioned routes: declaration, dispatch and remote authentication differ

[E02-F21](../reports/E02.md) has a direct deterministic path mismatch. Frontend `webui/src/lib/remote-access-api.ts:274–282` requests action `settings.remote_access.pairing.renew`; `nanobot/webui/settings_remote.py:149–153` implements `/api/settings/remote-access/pairing/renew`, but `nanobot/webui/settings_routes.py:137–148,379–397` excludes `pairing/renew` from `_REMOTE_ROUTES`, so the normal settings route cannot reach the implementation. Fix route admission and mutation classification together, or intentionally retire the unsupported UI action. Protect original owner auth, source binding and replay semantics.

[E02-F08](../reports/E02.md): session search can yield transcript-only records that session reader does not accept, an interface capability/identity contract (not “all search broken”). Either implement validated transcript-only read or exclude those rows from searchable hits. [E02-F19](../reports/E02.md) at `nanobot/webui/settings_remote.py:86–89` casts `enabled = bool(body.get("enabled"))`: string `"false"` takes the enable branch. Strict type/contract parsing belongs at the mutation admission edge, not scattered frontend only.

[R01-F04](../reports/R01.md): versioned `nanobot/remote/contracts/operations-v1.json` includes enabled HTTP transport rows that production `nanobot/remote/edge.py:301–488` does not implement in the same route/method shape; for example enabled `attachment.write` at `operations-v1.json:466–481` advertises POST `/mobile/v1/attachment` while production edge handles attachments through the typed `handle_ws_frame:615–633` branch, not that direct HTTP route. Do not infer that **all** mobile attachment flows fail: the actual WS transport is supported; the **declared HTTP route** is not. Other advertised bootstrap/mutation/logout mismatch details remain as originally qualified in R01. Derive route contract from supported production dispatcher or implement declared routes, with actual edge-router tests rather than a substitute server.

[R01-F07](../reports/R01.md) is different from missing routes: optional Tailscale pairing UI may offer a pairing link after substring-based Serve readiness or HTTPS-origin fallback without verifying the exact Serve→gateway mapping. Require exact verified readiness before a **Tailscale-only offer**; this is conditional and does not demonstrate bad default local pairing or an observed misdirected phone.

**Preserve authorization:** A generated action→route list must not replace mobile token/installation/command-specific scopes; I01 R01-F02 remains an independent **server-side** authorization requirement. Similarly a route in the UI is not proof that a plugin/runtime has been started or is ready.

## I03-G — Tool definition, plugin construction and MCP publication must describe admitted capabilities

[T01-F01](../reports/T01.md): arbitrary external JSON Schema can advertise constraints unsupported by local pre-dispatch validation; reject unsupported keywords at registration or explicitly implement their semantics. This is not permission to run unvalidated external tools just because the provider's tool schema looks well typed.

[T01-F02](../reports/T01.md): `ToolLoader._construct_plugins:132–202` calls each enabled plugin's `create`, validates later names/schemas and only subsequently publishes all tools in `ToolLoader.load:203–219`. Registry **publication** is atomic with duplicate checks but a construction side effect can survive a later failure because there is no general disposer; preserve plugin compatibility with a narrow constructor cleanup/side-effect-free factory contract. This is a resource lifetime question, also relevant to later release/operational qualification, **not** an assertion that all plugins leak.

[T01-F03](../reports/T01.md): at `nanobot/agent/delegation.py:307–325` concurrent first callers see `_mcp_connecting=True` and immediately return rather than awaiting the same connection readiness result; their delegated registry may omit intended read-only tools. **Do not replace this with unbounded blocking:** one shared init Future/owner-task wait with cancellation-safe joining is the small correction.

[T01-F05/F06](../reports/T01.md): in `nanobot/agent/tools/mcp.py:1351–1450`, wrapper registration occurs while a single MCP server is still being initialized and optional resource/prompt listing is incomplete. A later failure can leave dead registry entries; stage per-server wrappers and commit atomically or rollback that server. The stdio handshake (e.g. `await session.initialize()`) has no bounded readiness deadline under the existing serial startup path. Add a per-server deadline and retain per-server failure diagnostics; do not discard successfully ready independent servers or blindly retry effects. Dynamic MCP scopes/trust (I01 T01-F04) and parent registry dispatch remain independent, including live revocation.

**Smallest shared capability fact:** at each surface, distinguish **declared**, **configured**, **actually registered**, **connected and ready**, **authorized for current request**, and **completed effect**. They are not synonyms and should not become one mutable global flag.

## I03-H — Gated onboarding, local health, mobile fixture and cron management scope

[R01-F05](../reports/R01.md) identifies an **isolated mobile data-server fixture** whose refresh, mutation/replay, logout and WebSocket authorization differ materially from the production gateway/edge/router. Qualifying only that fixture cannot prove the production feature contract. Test the real composition with bounded side-effect dependencies; this I03 entry is **qualification fidelity**, not a newly observed production transport failure. Separate R01 release/toolchain and update-migration qualifications await the release integration stage.

[C00-F04/F05](../reports/C00.md) concern legacy CLI onboarding: `nanobot/cli/commands.py:325–335` calls `require_runtime_ready()` before either path; the current migration guard **always denies**, so neither unsafe second `open("w")` config-writing nor secret list/plaintext editor is a default-current reachable wizard behavior. If this path is reactivated, use the canonical atomic writer and sensitivity-aware masking/password-safe UI first. Do not treat gated code as deployed corruption or secret exfiltration.

[C00-F07](../reports/C00.md) is local readiness interpretation drift. Frozen `nanobot/cli/webui_support.py:398–420` parses bounded JSON then immediately calls `payload.get` without asserting that it is an object. A valid scalar/array JSON health payload can crash the local WebUI readiness helper instead of returning false, while the managed gateway has a distinct proxy-free, shape-checked health predicate. Preserve the concrete standard health producer as positive; a single bounded proxy-free parser/predicate in local management is smaller than a health-service framework. No network probe or actual crash was run.

[A01-F06](../reports/A01.md) is model-facing cron list/remove being **instance-global**: only a problem where an agent legitimately supports **mutually untrusted chats or users**. Define the product's creator/admin scope before changing list/remove semantics; an explicitly single-owner personal agent may intentionally retain global management. A shared capability manifest must not imply instance-global management gives the browser/agent arbitrary user scope.
