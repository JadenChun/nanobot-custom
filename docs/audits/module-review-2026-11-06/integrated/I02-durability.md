## Core integrated conclusion — a shared receipt vocabulary, **not one global state machine**

The nine streams already encode different truthful outcomes. A **canonical source event** is not a **request acknowledgement**; a **model terminal signal** is not a **completed tool effect**; an **admitted process** is not a **quiescent descendant tree**; a **credential hash stored server-side** is not **plaintext credential custody by the client**; an **HTTP/WS terminal event** is not **durable effect settlement**; and a **sidecar or transcript file** is not the **canonical session**. Reusing one boolean like `success`, `closed` or `replayable` to represent these across owners would create more uncertainty, not less.

The bounded simplification is a **common vocabulary for contract/projections**—*rejected before effect*, *known not applied*, *applied/committed*, *partially applied*, *uncertain*, *acknowledgement/delivery outstanding*, and *owner retained/released*—while **each existing source, scheduler, provider, channel, browser, storage, OAuth, native or UI owner** maintains its own durable proof and idempotency rules. A single universal transaction engine or an implicit “retry error” switch is **not justified**. External effect uncertainty must not be converted into a second execution simply because a response was lost.

### I02-A — Mandatory source writes must not look optional; effect and acknowledgement must be separate

[H01-F1](../reports/H01.md) is a concrete contract collision. At frozen `nanobot/session/turn_writer.py:69–99,140–179`, a required source append/consumed follow-up can poison the invocation's shared writer. But `nanobot/agent/runner.py:493–528` catches all ordinary callback exceptions from `_drain_injections` and returns an empty list, an older *optional injection* behavior. In the exact before-write/transient-store failure case detailed in H01, Runner can proceed or report success even though this canonical follow-up write was mandatory. **The original journal/republish retains the input**; do not claim loss of input or duplicate side effects. Tighten required versus optional callback contract and check writer poison before any subsequent model/success, while preserving old edge compatibility.

[H01-F2](../reports/H01.md) occurs at the *other end*: frozen `runner.py:1370–1477` records an earlier model/empty-response terminal `error` and `stop_reason`, then may accept an injection after an async hook and continue. Later ordinary success can retain the earlier terminal error into SDK/Loop projections. This is a terminal *presentation/state reset* issue, not a failed canonical write. H01-F6/F7 identify repeated request/turn/result aliases, dispatch ticket and recovery interpretations which make both classes harder to keep consistent. Narrow the private normalization, do **not** collapse source IDs, run IDs, user identity and per-request projection epoch into one ID. `SourceRequestLedger.issue/acknowledge/discard` at frozen `nanobot/session/source_request.py:143–181` is explicitly **a local projection ticket**, not durable proof that an external effect can be replayed.

[E02-F01](../reports/E02.md) is unmanaged SDK persistent ingest publishing a live metadata/message prefix before a later malformed item fails validation; validate a detached candidate before publishing it. [E02-F20](../reports/E02.md) is the opposite window: a WebUI mutation's business effect may commit while a subsequent response/followup fails. The durable replay records the resulting failure as “completed” and can suppress proper cache invalidation, not necessarily redo the effect. Frozen `nanobot/webui/replay_store.py:136–224` already has durable begin/completed/uncertain and a finite at-most-once window; `nanobot/webui/inbound_commands.py:1385–1539,1740–1763` uses it and records non-timeout results as completed. The smallest correction is **typed applied/unknown/not-applied effect semantics at the mutation executor boundary** and projection invalidation based on what committed, without bypassing the current replay's source binding or blindly retrying committed mutation.

**Proof matrix before repair:** mandatory follow-up write fails before append; persisted input remains republishable; model not re-requested after poisoned mandatory source; accepted later injection clears final error while history retains earlier attempt; ingest validation fails without mutating live prefix; effect commits then response/send/update fails, replay never repeats effect and correctly reports applied/unknown state.

### I02-B — Capacity limits must be admission limits or accompanied by safe archival, not post-success denial

[H02](../reports/H02.md) demonstrates two **independent** static ceilings. `source_store.py:1191–1225` serializes an entire appended canonical source before `session_mode.py` later applies the **64 MiB** per-source read limit; an already accepted source can become unreadable on later namespace resolution. `mode_storage.py:1054–1108` refuses directories over **4096 entries** before suffix filtering, while mode-journal activity retains historical proof. These are different readers and persistence shapes. H02-IO points to repeated resolver/whole-source/handle enumeration as an **unmeasured structural cost**, not license to remove fsync, replacement checks or history. Smallest coherent options are pre-admission serialized-size checks with an operator oversize recovery path, and indexed/current namespace plus independent archived proof; hard invariants must stay stable across crash/restart/retired sessions.

[A01-F04](../reports/A01.md) is **not** the H02 4096 directory: frozen `nanobot/cron/scheduler_store.py:45–62,570–595` caps classifications/requests at 4096 and entire scheduler state at 1 MiB. Scheduled timer advancement appends predecessor classifications without an installed epoch/rollover owner; source-proved finite lifetime eventually refuses further valid timer commits. Preserve exact cursor/evidence predecessor chain in any epoch archive. Move whole-history reproof off the shared async hot path only with atomic/current-index plus retained history/rebuild proof; see I02-E.

[E02-F07](../reports/E02.md) concerns **transcript rotation**: a segment may be made durable before active tail replacement, so a crash or IO failure can leave the same turn visible twice in segment+tail. This is a watermark/generation-pointer recovery problem, not an already-oversize canonical source or scheduler exhaustion. The direct frozen `nanobot/webui/transcript.py:678–723` appends/fsyncs active events and triggers rotation at `turn_end`; its independent segment/manifest sequence is documented in E02. Preserve transcript/display history versus canonical source. An atomic generation or reader watermark prevents duplicate projection without rewriting source events.

**Proof matrix:** 64 MiB crossing refused *before* visible success; 4096 journal growth under valid repeated session activity; scheduler end-of-cap with archived predecessor proof and crash in rollover; transcript crash between segment and tail generation; concurrent reader sees either old or new complete projection but not duplicate/omitted turn. Never “solve” caps by silently discarding mandatory history.

### I02-C — Provider terminal/route/custody outcomes differ from tool effects

[H03-F1](../reports/H03.md) is explicit missing Responses terminal validation. Frozen `nanobot/providers/openai_responses/parsing.py:34–76` records an actual terminal `response.completed` as success, yet the SDK iterator can end cleanly after output/tool data without such a terminal and the normal parsing path may present usable output. Treat EOF-before-terminal as a typed incomplete transport result. **Do not** retry after visible content/tool deltas unless existing no-replay policy allows it; `nanobot/providers/base.py:60–75` tracks externally delivered deltas before invoking callbacks. Preserve bound native state and exact request identity on success.

[H03-F3](../reports/H03.md) is fallback *model-request* duplication: a prepared primary fails fallbackably, fallback verification sees a stale route, and a reprepare may select the old primary again. Resume from an attempt-identified next candidate; this is **not** a proven repeated tool effect. [H03-F5](../reports/H03.md) is accounting granularity: one logical safe chat can issue multiple physical upstream calls, while one LLMCallRecord obscures the transport count. A measured cost figure is **not** asserted. Preserve logical turn budget and accurate physical request records without counting retries twice.

[H03-F2/F7](../reports/H03.md) are distinct OAuth intent races. Frozen `nanobot/providers/openai_codex_oauth.py:119–151,179–211` cancels a Future/joins briefly while an already in-flight worker may still publish if durable login intent was not superseded; another provider's two live login flows may complete last-writer-wins even after a newer one publishes. They need **generation-bound publication authority**, not a reissued login because a UI acknowledgement disappeared. H03-F2 has a narrow cancellation/expiry trigger; H03-F7 applies to overlapping xAI flows. Neither is identical to R01 device pairing/refresh credential custody.

**Proof matrix:** partial stream then clean EOF; externally delivered delta and terminal missing; fallback reprepare after one failed primary without reselecting it; physical attempt and logical usage record count; cancelled OAuth exchange completes later; concurrent flow generations persist only currently authorized token. No general provider adapter rewrite.

### I02-D — Native, CLI and SDK owners cannot release unknown running work

[S02-F01](../reports/S02.md) is specifically a yielded exec session with finite hard timeout and `notify_on_exit=False`: frozen `nanobot/agent/tools/exec_session.py:385–472` creates a deadline watcher only when a notification sink is present; with no later poll/stop/shutdown the timeout is not independently enforced. The minimal correction is a mandatory lifetime/deadline owner independent of optional notification. [S02-F02](../reports/S02.md), **also referenced in I01**, follows frozen `nanobot/agent/tools/shell.py:525–565`: native admission is durably reserved, then a second input validation may return before spawn and leave a “starting” reservation. A scoped unlaunched-reservation cleanup/transfer must cancel **only proven unlaunched** work, retain uncertain launched effects. [S02-F03](../reports/S02.md) is manager-lock scope through external waits; no measured contention is proven. Shrinking the lock may require more state than it saves and is lower urgency than correctness.

[C00-F01/F02/F03](../reports/C00.md) are three different composition/close failure windows, not “one cleanup bug.” Interactive CLI can acquire then fail during prompt/MCP setup before its cleanup try. SDK `aclose` at frozen `nanobot/nanobot.py:388–403` sets `_closed=True` **before** awaiting composition close, so a concurrent close or failed owned cleanup cannot be joined/retried through the facade. `RuntimeComposition.aclose` at `nanobot/runtime_composition.py:582–633` does have shielded close and FAILED owner retry with retained callbacks on successful graph construction; **C00-F03** concerns a custom partially constructed graph whose resistant rollback aborts before callbacks become a retained graph. An immediate acquired-scope try/finally, joinable SDK close result and retained partial-acquisition callbacks fix different owner lifetimes; preserve primary+cleanup error groups and original order. Built-in resistant partial constructor was **not** proven.

[E02-F14](../reports/E02.md) similarly concerns WebUI `skills.sh` installation descendants continuing after cancellation/timeout, with the WebUI installer as process owner; reuse managed owned process-range cleanup, but not automatic unsandboxed fallback. [R01-F06](../reports/R01.md) is opt-in systemd tooling reporting `applied:true` while `systemctl` exits nonzero; this is **outcome reporting**, not an orphaned child or remote service exploit. It requires one structured process status result before downstream actions.

**Proof matrix:** yielded/no-notification timeout; prelaunch revalidation failure consumes no native reservation; root exit but descendant remains; cancel after spawn/close; CLI setup fails before interactive loop; two SDK close callers join; failed close retains retryable work; injected factory fails with resistant closer; installer process grandchildren on cancellation; nonzero systemctl cannot report applied. OS-specific Linux proof and Windows Job capability must stay distinct.

### I02-E — Cron and process completion: persist state off the event loop, but never weaken effect fences

[A01-F01](../reports/A01.md) is source-confirmed synchronous SQLite FULL durability on process-continuation callback hot paths. Frozen `nanobot/process_completion.py:49–88,145–212` journals transitions, marks interrupted work unknown and refuses to blindly replay already `dispatching` work; **keep those guarantees**. [A01-F03](../reports/A01.md) is a separate synchronous cron scheduler fsync/history reproof path on the timer event loop, supported by frozen `nanobot/cron/runtime.py:198–255` calling scheduler wake and `scheduler_store.py` read/fsync validation. One **ordered async persistence lane pattern** may be reused where durability-before-effect requirements align; retain separate data models, locks, store authority and exact before-effect barriers. Latency benefit is hypothetical until measured.

[A01-F05](../reports/A01.md) retains terminal outbox dispatch/task entries for the store process lifetime even after durable claim consumption. Terminal cache eviction can occur only after true waiter settlement and must not erase durable send evidence. Frozen `nanobot/cron/delivery_runtime.py:373–430,666–763` is a positive owner for distinct ConfirmedDelivered/ConfirmedNotSent/PermanentNotSent/UnknownOutcome and durable settlement exception; do not replace this by a single boolean. [A01-F07](../reports/A01.md) is the deliberately inactive default local-trigger queue behind advertised command surfaces; enabling it is a **D4 feature choice**. Only **if activated**, [A01-F08](../reports/A01.md) becomes a P1 conditional replay hazard: frozen `nanobot/triggers/local_runner.py:20–97` recovers processing files/retries interrupted delivery independently of whether the canonical turn had already committed. Bind delivery ID to canonical source settlement and requeue only when **absence is proven**; unknown stays inspectable, not auto-replayed. A01-F09's untrusted automation consuming approval is outside I02's counted IDs and remains a separate **D2 authority blocker**, already recorded in A01 but requiring eventual integration.

**Proof matrix:** artificial slow SQLite/fsync with event-loop responsiveness but exactly ordered commits; crashed process waiting/dispatching → unknown not replay; cron append/epoch crash; outbox sender known not sent vs unknown; disabled trigger command unavailable; enabled local trigger commits turn then crashes before deleting processing file—no second original tool effect; background approval denied without user provenance.

### I02-F — Mobile credential custody and native completion are separate incidents

[R01-F01](../reports/R01.md): desktop pairing persists a device and its refresh hash before the client acknowledges custody of the only plaintext credential pair; an interrupted response/restart can leave a server-issued identity unusable by the phone. [R01-F03](../reports/R01.md) is **different**: rotation invalidates old refresh/access before the client safely receives the replacement. Frozen `nanobot/remote/auth.py:118–148` rotates then returns the new plaintext pair. Shared *custody receipt* vocabulary is useful, but pairing enrollment and refresh rotation have distinct prior-state/rollback semantics. Do not casually preserve indefinitely valid duplicate refresh tokens.

[R01-F08/F15](../reports/R01.md) are Android pending pairing owner state: manual code's poll challenge is volatile and process death loses it, while Cancel of QR/link pairing clears only volatile bootstrap, allowing encrypted pending state to restore unexpectedly. Persist manual challenge with bounded encrypted lifecycle and implement durable cancellation fenced against in-flight collection. These are not proof of remote authority acquisition or a login failure on every attempt.

[R01-F09](../reports/R01.md) is a request-ID **registration race**: a native HTTP result can arrive before JS waiter registration. [R01-F13](../reports/R01.md) occurs **after admission**: terminal HTTP/WS events can be dropped if native Go broker event queue is full. Direct frozen `mobile/native-network/internal/broker/events.go:1–46` shows nonblocking `emit` returning ErrQueueFull and `PollEvent` retaining too-large head entries. [R01-F10](../reports/R01.md) is yet another blocker: an allowed WS frame can expand beyond the fixed JNI output buffer, so the next oversized queued event is retained indefinitely. Neither queue-error nor buffer repair fixes the early registration race. [R01-F12](../reports/R01.md) is unsynchronized C `last_error` pointer ownership under concurrent JNI readers; it is a memory lifetime/synchronization issue, **not** a missing terminal event.

**Proof matrix:** pairing response lost before client storage, rotation result lost, restart with manual/QR pending, Cancel then delayed desktop approval, immediate native completion before waiter, full broker queue and reserved terminal event capacity, oversized retained event with forward progress, concurrent native error copy. Preserve server revocation/refresh validation and Android Keystore custody as positive boundaries.

### I02-G — Durability of delete/prune and truthful session/media availability

[M01-F01](../reports/M01.md) shows attachment migration `--dry-run` can write canonical blob/sidecar while only transcript rewrite is gated. A dry-run must not change any canonical store unless a separately defined preview scratch area is used. [M01-F02](../reports/M01.md) leaves metadata sidecars after blob prune; reclaim matching sidecar **only after** validating shared blob/reference identity and byte-retention expectations.

[M01-F04](../reports/M01.md) is materially more serious: frozen `nanobot/attachments/lifecycle.py:44–99` catches unreadable/invalid session events and continues, then explicitly authorized `prune_unreferenced` treats an empty or incomplete reference scan as evidence no blobs are in use. This may delete referenced bytes under a manual prune; **not automatic background deletion**. Fail closed on missing/unreadable/corrupt canonical reference sources, account for pending upload IDs and cross-session roots, and require explicit operator reconciliation. A partially readable JSONL cannot count as a complete “safe to delete” proof.

[E02-F03/F05/F06/F09/F10](../reports/E02.md) are related to reference ownership but not one GC defect: Windows drive/UNC generated asset references missed in scan; colliding normalized transcript filename identities; canonical session deletion that reports success while readable transcript copy remains; Temporary Chat unlink failure dropping retry ownership; and discarded temporary tombstones retained without bound. The first two require platform-correct/reversible identity; deletion completeness requires structured complete/partial outcomes and persisted or bounded retry/quarantine; tombstones can expire only when no live reference/proof needs them. **Do not delete canonical session history merely to make projected media cleanup look successful**.

**Proof matrix:** dry-run no blob/sidecar bytes; shared hash with multiple logical refs; empty/wrong directory and unreadable/invalid JSONL causes prune refusal; accepted upload pending but no session row; Windows absolute path, normalized chat-ID collision, transcript cleanup failure, Temporary Chat unlink failure and safe tombstone expiry. Keep canonical session and WebUI display artifact independently accountable.

### I02-H — Bound expensive work *before* allocation, not only model-visible output

[R01-F14](../reports/R01.md) is 512 MiB mobile media-cache budget enforced after writing a full temp file; account in-progress and per-object bytes while preserving network streaming if caching stops. [M01-F03](../reports/M01.md) passes caller-supplied audio `duration_ms` to an apparent maximum-duration check, but actual audio length is not verified; decide whether duration is **authoritative policy or advisory UX** and enforce accordingly. [M01-F05](../reports/M01.md) reads unbounded reference images for signature/content then again in provider base64 projection; check count/byte ceiling at model-bound input and stream header separately. [M01-F06](../reports/M01.md) checks `len(contents.get_data())` after full PDF expansion, so nominal 32 MiB decoded-content limit is not a pre-decode guard. [E02-F23](../reports/E02.md) loads an unrestricted no-query WebUI transcript path around the standard projection budget. These have distinct parser, gateway, provider and cache owners; share a **budget vocabulary**, not a common parser/GC engine.

The adjacent [T01-F11](../reports/T01.md) unbounded `web_fetch` pre-truncation download is **cross-reference only** in this I02 stage and remains for the later tool/resource integration. Model-visible output caps, uploaded transport frame caps, decoded PDF expansion and storage cache high-water marks are different byte boundaries.

### I02-I — Conditional simplification and legacy source/receipt safety

[H02-ART-SOURCE](../reports/H02.md) observes possible duplication between a canonical committed tool-text source and an opaque immutable artifact byte copy. Source-backed range reads might reduce persisted copies, but **opaque ID is not access**, and exact hash/event/execution/grant/location/UTF8 byte-offset plus migration/restore promises cannot be dropped. It is **an optional later proof of concept**, not an implementation recommendation now.

[H02-LEGACY-ISOLATE](../reports/H02.md) proposes isolating offline recovery/receipt finalizer stages from hot runtime after preserving exact historical conversion/terminal-proof/clean-absence semantics. Do not turn missing sealed historical files into “already migrated.” [H02-IDLE-DORMANT](../reports/H02.md) records the idle compaction feature lacks production activation; keep this separate from actively used archiver/compaction/checkpoint functions. Retirement requires public caller/storage/compatibility checks, not just a no-in-tree-call observation. These three are **recorded source-ledger alternatives** with source constraints and are **not promoted as new live incidents by I02**.

## Sequential implementation candidates and deterministic proof gates — **not accepted choices**

1. **Blocker correctness before optimization:** mandatory source write poison/failure and native unlaunched cleanup; committed WebUI mutation response classification; mobile terminal event survival; source-delete/prune fail-closed. Condition priorities remain those in original module reports.
2. **Bounded capacity without erasure:** canonical source 64 MiB pre-admission policy; mode 4096 proof-directory strategy; scheduler 4096/1 MiB epoch archival; progress and retention of active native/media/terminal state. Keep deterministic crash/restart semantics.
3. **Outcome and lifetime ownership:** provider terminal+fallback attempt/cancellation, SDK close join/retry, paired/rotated credential custody, native-sized event retrieval. Effects already known applied remain applied even when notification fails.
4. **Only after correctness and D4/D5/D6/D7 policy:** move synchronous durability to ordered async workers; simplify repeated source/usage/terminal projections; candidate legacy/idle/opaque-blob retirement and optional feature activation. Measure before claiming performance wins.

Future tests require fault injection at **before effect / after effect / before durable commit / after durable commit / before ack / after ack / cancellation / restart**, with immutable IDs, authentic owner proofs, session/route/credential generations, typed outcomes and crash-recovery assertions.
