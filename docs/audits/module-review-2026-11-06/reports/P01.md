## Overall structural judgement

**Keep the architecture and simplify along already existing owners. Do not replace the agent loop, messaging model, cron/remote ledger, shell sandbox, tools, React state, mobile native bridge or media storage wholesale.** The strongest components already make hard distinctions that should survive cleanup: identity versus scope, source versus display projection, accepted versus applied versus acknowledged versus unknown, direct process exit versus descendant quiescence, app-level path denial versus kernel sandbox proof, credential issue versus client custody, and canonical record versus temporary/cache materialization.

The best strategy is **coordinated small patches per owning module** with narrow cross-layer contract tests, not one sweeping abstraction PR. Ten candidate simplification packages follow; their IDs **P01-C01–C10 are proposals, not new audit findings or accepted repairs**. Priority is an *ordering suggestion*, separate from original finding severity and user decisions. A cross-module package may share one contract yet still require several distinct implementation owners.

## Ranked simplification packages

### P01-C01 — One effective path and permission decision; preserve different enforcement planes
**Order: foundation before convenience; high security consequence, medium/high semantic risk.**

- **Source convergence:** S01-F01 finds Full/Once UI effective-access shortcuts that diverge from ResourceAccessPolicy; T01-F07 and K01-F01 show browser/device output and prompt/skill path reads outside the same path authority; X01-F01 proves CLI App cwd-only restriction cannot confine a host child. H01-F4 concerns a risky approval reading a different root from execution; K01-F06 and T01-F08 concern approval of nested agent/global desktop input. X01-F02 concerns browser read-only classification that invokes a DOM click. R01-F02 and T01-F04 are *different* remote/delegation authority problems, not path-parser duplicates.
- **What becomes smaller:** give existing ResourceAccessPolicy one typed per-call path decision/facts interface, used by scope display and all managed path *eligibility* checks; retire shortcut copies of root precedence and private-path checks, making approval inspect exactly the prepared target. Derive runtime/read-only labels from the true permitted capability and side-effect class, not prose or untrusted MCP hint.
- **Do not collapse:** filesystem path mediation, OS child sandbox, native task/source proof, remote role scopes, MCP trust tiers, browser action audit and explicit risky-action approvals are **different authorities**. App-level checks must never be described as kernel confinement. Restricted CLI Apps require actual supervised sandbox capability or fail-closed disablement, not only argv screening. A delegated crawler page interaction must stop synthesizing a click if it is promised read-only.
- **Proof before change:** protected/context repo path precedence across Sandbox/Once/Full; symlink/replaced path races; approved target equals executed target; source/task/grant revocation; Windows/Linux support matrix; MCP read-only untrusted hints; local authenticated worker caller proof. Owners S01/S02/T01/K01/H01/X01/Q01/R01. Decisions D1/D2/D3/D4/D5.

### P01-C02 — Explicit per-gateway instance roots and dependency injection
**Order: high leverage when multi-instance support is accepted; medium/high compatibility risk.**

- **Source convergence:** C00-F06 shows explicit SDK Config roots coexisting with process-global media/network policy. E02-F11/F13/F15/F16/F17/F18 identify global CLI-App, MCP, folder grants/private root, OAuth, remote-owner socket and usage stores despite explicit gateway config paths. H03-F4 adds ambient Bedrock bearer mutation. E02-F15/F16/F17 are independently consequential authority concerns and must **not** be demoted to mere duplicated metadata.
- **What becomes smaller:** capture one immutable instance-root dependency graph at composition and inject its narrow store/factory roots into existing services; remove repeated global path resolution in per-request paths. Use a stable credential profile and usage store identity so settings and actions agree. Prefer passing one typed instance-context object to actual constructors over a new global service locator.
- **Choice boundary:** if only one gateway instance per OS process is supported, say so and enforce it; this may reduce migration scope, but still repair custom-path writer/reader mismatches. If multiple instances are supported, define explicit sharing of credentials and remote authority instead of inheriting global defaults.
- **Proof:** two synthetic config roots; no cross-instance token, media, owner-socket, grant or usage coupling except explicitly shared resources; CLI default behavior stays compatible; capture once, no switching globals around awaits. Owners C00/E02/S01/H03/X01. Decisions D2/D4/D6/D7.

### P01-C03 — Typed effect outcome, settlement and receipt vocabulary, not one persistence engine
**Order: foundational semantic choice; high migration/compatibility risk.**

- **Source convergence:** E02-F20 observes committed WebUI mutation replaying as failure; H01-F1/F2/F6/F7 distinguish mandatory follow-up, stale terminal fields and repeated settlement projections; H03-F3/F5 distinguish prepared fallback attempts and logical versus physical provider calls. A01-F08 warns against automatic trigger replay after committed effects. R01-F01/F03 are separate credential issuance and rotation custody windows; R01-F09/F13 separate waiter-registration and terminal-event backpressure failure.
- **What becomes smaller:** define a minimal typed outcome/receipt lexicon at existing owners: *not applied*, *applied with delivery/notification outstanding*, *uncertain*, *rejected before admission*. Bind idempotency keys and logical/physical attempt IDs at the correct boundary; let public projections consume one authoritative fact rather than re-guessing from booleans and error strings. Share contract vocabulary/testing, **not** one global transaction coordinator, DB, retry queue, or default retry behavior.
- **Do not collapse:** provider terminal output, tool effects, source event commit, cron occurrence, WebUI mutation acknowledgement, mobile transport completion and client-held refresh secret are **not the same event**. Do not reissue a token/trigger or replay a tool just because a display/transport ack was lost. Preserve no-retry-after-visible-delta/provider native-state fences and conservative unknown results.
- **Proof:** failure at every before/after-write and before/after-ack boundary; repeated call with same idempotency key, cancellation, native terminal event dropped under pressure; replay only when nonapplication is proved. Owners H01/H02/H03/E02/A01/R01. Decisions D5/D6/D7.

### P01-C04 — Small asynchronous identity/generation fence at UI adapters
**Order: near-term small diffs; low/medium risk.**

- **Source convergence:** U01-F02/F03/F04 are all stale completion into a different session, channel or skill; D01-F02 is the analogous TUI /context request crossing sessions. U01-F01's queued attachment-only prompt uses a different sendability predicate; D01-F01 consumes queue before send acceptance. These queue errors are *not* stale-completion defects.
- **What becomes smaller:** keyed component remount where local identity ownership already exists, otherwise a tiny generation check in async success/error/finally; reuse per-component existing request identifiers, not an application-wide request manager. Define exactly one sendability predicate per queue and change removal from **take-before-send** to **peek then commit after local admission**. Keep UI optimism and server replay semantics separate.
- **Proof:** switch A→B before A resolves/rejects, concurrent same-identity requests, socket/credential reconnect, empty attachment-only prompt FIFO, rejected local send without discarding payload, retryable optimistic persistence failures. Owners U01/D01; E02 provides server mutation admission. Decisions D5/D6/D7 if a wire contract changes.

### P01-C05 — Reuse the existing supervised process/child-lifetime contract
**Order: security/reliability before feature expansion; medium/high platform risk.**

- **Source convergence:** S02-F01/F02/F03 show missing independent hard deadline owner, orphaned reserved native admission on prelaunch denial and long external waits under the session manager lock. T01-F09 and E02-F14 show generic subprocess/installer descendants surviving cancellation; X01-F03 captures unbounded CLI stdout/stderr; X01-F01 starts host CLIs without the managed shell's sandbox authority. T01-F12 identifies thread-backed VPN session handle loss on cancellation.
- **What becomes smaller:** make process adapters invoke a *single already-owned execution/supervision primitive appropriate to their platform* with bounded stream reading and independent timeout/termination; share handling of root PID versus descendants and completion receipts. Let the existing shell/native owner handle reservation/unlaunched cancellation rather than building a second lifecycle engine.
- **Do not collapse:** subprocess helper and browser worker and optional systemd service are separate principals with different IPC/OS contracts. No silent native fallback when sandbox proof is required; Windows Job and Linux adopted-tree receipt semantics are not identical. Do not put blocking awaits under the existing session-manager lock.
- **Proof:** pre-spawn rejection, root exit with active descendants, cooperative cancellation and forced kill, output floods, timeout without polling, concurrent process allocations, Linux/Windows capability evidence. Owners S02/T01/E02/X01/Q01. Decisions D1/D2/D5/D6/D7.

### P01-C06 — Capability manifest and endpoint contract derived from actual registrations
**Order: small feature-specific fixes early; broader generated contract only after D4.**

- **Source convergence:** T01-F10 and K01-F11 both cover missing core apply_patch while prompt guidance advertises it (**shared contract, not two independent implementations**); K01 also exposes missing grep/find_files. A01-F02 and A01-F07 concern visible /goal and /trigger with absent registered tool/consumer; K01-F04/F09 describe stale cron/browser skill guidance; E02-F21 proves remote pairing renewal route omitted; R01-F04 and R01-F19 reveal declared/mobile parity route drift and an async AST checker omission.
- **What becomes smaller:** preserve the existing explicit core tool manifest and domain route registries; produce a narrow capability fact set for prompt/guidance/feature availability, and add deterministic parity checks from real dispatch tables to intended client calls. Fix each unconditional registration mismatch locally before considering code generation. A shared schema/check utility is justified only where both consumers actually need the same contract.
- **Do not conflate:** prompt instructions, tool-dispatch registry, typed WS commands, HTTP routes, process worker readiness and remote scope permissions have different activation and authorization rules. A flag enabled in config is not a running consumer. External public aliases cannot be removed merely because in-tree calls were not found.
- **Proof:** registry/capability snapshot tests, direct and async route declarations, user-facing disabled state for inactive runtime, fallback behavior across custom plugins and frozen skills. Owners T01/K01/A01/E02/R01/C00. Decisions D3/D4/D5/D7.

### P01-C07 — Bounded history, archival and expensive reads at each state owner
**Order: protect durability and availability; medium/high storage design risk.**

- **Source convergence:** H02-CAP-SOURCE64 and H02-CAP-JOURNAL4096 show accepted source/journal growth later preventing resolution; H02-IO shows repeated namespace/header/source/handle scans and whole-source serialization; A01-F03/F04 show synchronous full-history reread and finite append-only scheduler proofs; A01-F05 and E02-F10 retain terminal entries/tombstones; E02-F04/F23 load limited session indexes but large transcript projections; M01-F04 says destructive prune must not turn missing session evidence into zero references; R01-F14 bounds media cache only after full write.
- **What becomes smaller:** at **each existing state owner**, choose bounded indexed current-state view plus independently retained history/archive, short-lived terminal caches, and explicit capacity/refusal at admission. Reuse already proven fsync and generation receipts; do not reduce durable proof to fit a cap or silently truncate a source. Move scheduler full-history reproof to bounded change/epoch evidence and observe exact retention/writer locks.
- **Do not collapse:** canonical source log, cron evidence, WebUI transcript projection, attachment hash retention and Android streaming cache have different replay/authority guarantees. A general-purpose GC for all is counterproductive; media prune must fail closed on incomplete references and not auto-delete user data. Source-backed artifacts replacing copied blobs (H02-ART-SOURCE) have significant opaque-ID, grant, byte-offset and migration obligations and belong to a *later optional* proof-of-concept, not an accepted rewrite.
- **Proof:** crash between write/manifest/pointer commit, exact earlier proof, 64 MiB/4096 boundary, orphaned/replaced roots, live in-flight uploads, content hash, terminal retained work, page continuation, bounded I/O under sustained schedules. Owners H02/A01/E02/M01/R01; decisions D5/D6/D7.

### P01-C08 — Ordered async persistence owner for gateway hot paths
**Order: significant potential source-visible event-loop reduction; medium durability risk.**

- **Source convergence:** A01-F01 and A01-F03 independently place synchronous FULL SQLite/persistence and fsync history scanning on the shared event loop; H02-IO adds analogous read/rewrite overhead but with a distinct source-store transaction. S02-F03 holds a manager lock through external waits. These are *different* bottlenecks, not evidence for one database or a universal worker pool.
- **What becomes smaller:** one **ordered async scheduling/persistence lane** for process-continuation and cron work if they share the same precise pre-effect durability barrier; make acknowledgements await the required durable commit while expensive sync I/O runs off the event loop. Narrow expensive immutable-history scanning before moving it. Let H02 source lifetime remain independently owned unless a real common transaction is proven.
- **Proof:** exact before-launch/after-commit ordering, crash/restart preservation, same-key ordered writes, outstanding cancellation/closed owner behavior, event-loop progress under synthetic slow fsync; no assertion of measured speedups. Owners A01/H02/S02, decisions D5/D6/D7.

### P01-C09 — One release provenance rule, implemented in existing build/deploy adapters
**Order: medium effort, high operational value, no new orchestrator.**

- **Source convergence:** Q01-F03/F04/F05/F06/F07 distinguish pipx installed/run environment, nonfrozen Hatch frontend install, in-place upgrade without rollback, historical P0 verifier drift and executable migration files excluded by CI. Reuse CI build and offline P6 release-inspection boundaries; do not introduce a new cross-language build system. Prepare versioned gateway runtime before switching, preserve previous artifact, and remove sign credentials from non-signing phases.
- **Do not collapse:** P0 historical reproducibility, Python wheel/Hatch WebUI, Docker, TUI Bun, Android Gradle/Go/Capacitor and deploy systemd have distinct packaging trust roots. A frozen-lock assertion is not proof a release passed runtime tests.
- **Proof:** reproducible same-source rebuilds, actual wheel/web bundle presence, different prior/candidate mobile release identities, frozen cached toolchain hashes, scoped signing env, failed-install rollback, CI changed-script triggers. Owners Q01/R01/E02/D01/C00. Decisions D4/D6/D7.
