## Seven qualified source findings

### Q01-F01 — P1 conditional: authenticated Windows crawler accepts unauthenticated loopback requests

**Requirement:** when an authenticated local browser profile may be reached by local principals outside the trusted agent, caller identity must be enforced rather than treating every loopback process as the agent. **Chain:** deploy/scripts/start_local_marketing_agent.ps1:54–78,98–122,150–212 launches a worker with user-data-dir, headed Edge, 127.0.0.1 TCP; setup_local_crawl4ai_profile.ps1:40–64 confirms operator sign-in. nanobot/crawler/worker.py:94–122,623–630,692–732,826–850 accepts a JSON object from any connected socket without request credential or peer user identity; an open request can initiate a session and return profile-visible content, and reset is exposed. The tool's own client rejects generic click, and worker imposes HTTPS/allowlist/DNS rules; these do not authenticate the local caller. **Trigger/impact:** enabled Windows profile and an untrusted same-machine account/process able to connect to the port; it could request read/inspect and reset. No LAN exposure, real data theft or multi-user deployment was proven. **Confidence:** high mechanism, conditional threat boundary. **Smallest repair:** per-worker random authorization capability in authenticated IPC, or OS ACL-protected named pipe; preserve Linux systemd Unix socket 0660. Cross X01 O2, S01, E02, D2/D4.

### Q01-F02 — P2 conditional: deployed-instance audit can disclose secrets in raw diagnostics

**Requirement:** declared redaction must apply to all emitted audit data. **Chain:** scripts/audit_deployed_instance.sh:1–14 states no secrets; :79–121 redacts some JSON config fields, but :32 dumps ps command lines and :55–56 prints git remote -v without redaction. **Trigger/impact:** tokens embedded in command arguments or HTTPS Git remote userinfo and audit log saved/shared. This can expose credentials; no real secret observed. **Confidence:** high for unfiltered source, conditional values. **Smallest repair:** print executable/PID rather than raw argv; mask remote URL userinfo/query and avoid arbitrary private cron fields. Script remains read-only. Cross E02/R01/D2/D7.

### Q01-F03 — P2: pipx verifies/runs a temporary environment instead of its installed executable

**Requirement:** post-install version and setup must operate on the package just installed. **Chain:** scripts/install.sh:76–85,145–149,289–321 and scripts/install.ps1:108–125,178–186,312–346 call pipx install then pipx run --spec nanobot-ai nanobot for version/setup. Official pipx documentation https://pipx.pypa.io/stable/how-to/run-scripts.html confirms run uses a separate cached temporary environment. **Trigger/impact:** pipx fallback and divergent cached/resolved release versions; version check/setup need not match the installed version. No observed mismatch. Official uv semantics differ: uv tool run can use an already installed tool (https://docs.astral.sh/uv/concepts/tools/); do not generalize this finding to uv. **Smallest repair:** invoke the persistent pipx-installed executable for verification/onboarding. D1/D6.

### Q01-F04 — P2 conditional: non-frozen frontend dependency installation in Hatch build

**Requirement:** release packages should be reproducible from an explicit lock/source identity. **Chain:** hatch_build.py:63–103 activates nanobot/webui/build.py:187–218,269–292, whose build step invokes bun/npm install without --frozen-lockfile / npm ci, then run build. .github/workflows/ci.yml:268–302 instead uses bun install --frozen-lockfile; Dockerfile:1–11 uses npm ci; pyproject.toml includes built dist. Source freshness is mtime-based. **Trigger/impact:** release build under different dependency resolution or cached dist may diverge from CI validated assets. No actual mismatch measured. **Smallest repair:** consistently frozen frontend install and source/lock/bundle digest recorded with the wheel/sdist; preserve local editable skip. Cross U01/D6/D7.

### Q01-F05 — P2 conditional: gateway update advances source before deployment success

**Requirement:** failed updates should leave explicit previous release and rollback. **Chain:** deploy/scripts/update_nanobot_gateway.sh:27–44 pulls/switches new Git revision before deploy_nanobot_gateway.sh:29–124 installs into existing venv, migrates config and restarts systemd. It has no transaction, staged tree, rollback or clean commit receipt. **Trigger/impact:** pip failure or restart/config error after Git update leaves source/env/service inconsistent, with an operational recovery decision. No outage observed. **Smallest repair:** stage/rehearse versioned release, switch only after verified installation, keep previous path and rollback receipt. Cross C00/R01/D6/D7.

### Q01-F06 — P2 conditional: P0 frozen source review uses mutable helper and dependency freeze

**Requirement:** historical reproducibility includes toolchain/verifier provenance, not only the archived application. **Chain:** docs/migration/run-p0-baseline.sh:4–16 pins old Git commit but reads verify-p0-archive.py and p0-baseline-requirements.txt from current repo; later invokes live verifier and installs from live freeze before recording its hash. verify-p0-archive.py:112–174 strongly verifies archived blobs, but not helper provenance. **Trigger/impact:** current helper or freeze drifts while same old archive commit is used, making historical runs incomparable. The tool is a previous P0 baseline, not current runtime release. No false result observed. **Smallest repair:** pin exact helper and requirements digests or extract them from immutable toolchain archive. D5/D6.

### Q01-F07 — P2 conditional: executable migration code can bypass CI by residing under docs

**Requirement:** modifications to executable migration helpers need relevant CI even when changed alone. **Chain:** .github/workflows/ci.yml:1–30 has push/PR paths-ignore docs/**; assigned primary executable files docs/migration/run-p0-baseline.sh and verify-p0-archive.py are under docs, so editing only them skips the workflow entirely. The internal change detector also classifies docs as non-code. **Trigger/impact:** migration code-only change receives no workflow gate; other workflows/branch protection were not ruled out, no regression shown. **Smallest repair:** move executables under scripts/migration, or narrow docs ignore to prose and include docs/migration executable extensions. D6/D7.

## Challenged leads not promoted

P6 archive is read wholly into memory before checking members, but it is an explicit local operator archive, not a public ingest endpoint; no size incident was demonstrated. P6 is a **static archive/contract and copied-state** rehearsal, not proof of systemd/real provider readiness. uv.lock is intentionally ignored and the dependency report explicitly records unlocked status, so do not assert a promised fixed lock invariant. BasedPyright diagnostic ratchet PASS_NO_NEW_DIAGNOSTICS allows existing debt and is not the same as a clean zero-diagnostic build. Linux crawler has an OS service account, socket permissions and memory cap, so the Windows loopback case does not apply wholesale. Windows launcher handles owned-worker cleanup, but descendants/job-object behavior remains S02/T01. Contributor updater targets HKUDS upstream; intended fork attribution is unknown. Six .pyi bodies are static interfaces and were not runtime-validated.
