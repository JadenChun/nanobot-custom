## S02-F01 — Yielded hard deadline depends on notification ownership

**Classification:** reliability/resource defect; **priority:** high; **confidence:** high
for a finite initial yield, root still running, default `notify_on_exit=False`, and no later
poll/stop/shutdown. This is a source-established conditional path, not an observed runaway.

`shell.py:130` and schema `169–172` promise a hard timeout.
[`_ExecSession:147–184`](https://github.com/JadenChun/nanobot-custom/blob/9562e57f8333d7f14b6aaeae837660723a9b2650/nanobot/agent/tools/exec_session.py#L147-L184)
stores a deadline and starts output readers without a timer. Poll `272–274` enforces it only
when polled while the root runs. Start `396,447–450` creates `_watch_completion` only for
notification with a sink. `_cleanup_locked:613–625` runs on later manager access and checks
idle age. The stated trigger therefore has no independent hard-deadline owner.

A minimal deadline task or one mandatory process-lifetime watcher would close the gap.
The analyst recommends the watcher with notification as an optional consumer: every admitted
session retains scheduling ownership independently of notification choice/initial cancellation.
Preserve live stdin proof, root-versus-tree distinction, failed-kill ownership and raw output;
the watcher must not drain foreground output merely to enforce a deadline. This does not
choose a wider public result or completion-transcript contract (D6/D7).

Later deterministic acceptance should use clock/event-controlled fake processes: finite
yield plus notifications off and no further calls terminates once at deadline and reports
`timed_out`; timeout zero remains unlimited. Account for notification on/off, initial
cancellation, normal exit, stop/shutdown races and failed termination retaining inspectable
ownership/unknown durable effects. Root exit must not falsely establish descendant quiescence.
These are future checks, not tests executed in this review.

## S02-F02 — Prelaunch input denial abandons an already-reserved admission

**Classification:** data-integrity/recovery defect; **priority:** medium; **confidence:** high
when external filesystem/store-health change makes the second approved-input check fail.

[`shell.py:539–554`](https://github.com/JadenChun/nanobot-custom/blob/9562e57f8333d7f14b6aaeae837660723a9b2650/nanobot/agent/tools/shell.py#L539-L554)
reserves native admission then can return immediately on `_revalidate_input_files` failure.
The outer `execute:486–505` removes staged snapshots only; foreground/session-manager
reservation cleanup begins later. Revalidation `410–426` can reject a changed resolution,
denied path or disappeared snapshot. A durable `starting` row can remain despite no child
launch, become conservative `unknown` at restart and block later activation or consume
bounded ledger capacity. **This is not the rejected event-loop retirement race and grants
no additional process authority.**

The smallest recommended correction is a scoped reservation owner immediately after
reservation, covering every prelaunch return/exception, with explicit transfer when spawn
or session ownership takes responsibility. Cancel only proven unlaunched reservations;
retain unproven launched effects under cancellation/failure. Preserve exact snapshots and
revalidation. Commit `88acd736c2` introduced the later return; restore ownership rather than
weakening the validation.

Later deterministic acceptance: inject the second resolver/policy denial after a real
temporary-ledger reservation but before mocked spawn. Spawn stays uncalled, no starting row
remains, snapshots are cleaned and repeated attempts do not exhaust capacity. Preserve
successful foreground/session handoff and unknown state if the launch gate could have opened.
