## Architecture judgement and preserved strengths

**Provisional Keep + Simplify.** Keep the current Desktop ownership model: strict versioned local IPC, independent gateway identity verification, explicit persistent-gateway lease semantics, uncertain-start/stop handling, process birth/listener proof, private native runtime ownership, remote-origin Tauri command denial and fail-closed quit. Keep the TUI's per-session queues, hydration/session generations, bounded transcript projection and Desktop identity check. Simplify two local state transitions: queued follow-up delivery should be transactional with send admission, and session-scoped async reads should share a consistent identity/generation fence.

## Promoted findings

| ID | Priority | Classification | Trigger and bounded consequence | Smallest useful alternative |
| --- | --- | --- | --- | --- |
| **D01-F01** | P2 | Automatic follow-up dequeue can lose a queued prompt when send fails | Idle auto-drain shifts the first follow-up, then `client.send()` throws because transport is no longer open. The TUI shows retry status but the dequeued text is neither queued nor restored to the composer. | Peek/commit dequeue after successful local send, or restore/requeue the exact item on failure. |
| **D01-F02** | P2 | `/context` completion can overwrite a newly switched session | Session-A context request resolves after switching to B; the old response updates B's context tokens/title/panel because `openContext()` lacks the chat/generation fences used by neighboring reads. | Bind `/context` completion/error commits to the captured chat/request generation. |

## Cross-cutting simplification direction

F01 does not need a new queue framework: the queue already owns per-session FIFO state, edit/restore and visible preview. The smallest change is to make dequeue transactional with send admission. F02 does not need a new data layer: the app already has `hydrationId`, `sessionLoadId`, `sessionMetadataId` and chat checks. Reuse one request-generation helper for all session-scoped reads instead of leaving `/context` and connection-rotated discovery as exceptions.

## Retained observations and deferred questions

- **D01-O1/O2:** the Desktop security/lifecycle spine is strong and should be preserved: loopback + secret + exact gateway identity/version/capability validation, private runtime/socket ownership, remote-origin command denial, captured-handle process proof and explicit uncertain lifecycle states.
- **D01-O3:** the earlier U01 “HostWebSocket/pre-open close orphan” shorthand is retired. There is no literal symbol by that name; the TUI resolver checks `closedByClient` before late WebSocket construction, and Desktop lease release intentionally leaves the persistent gateway alive.
- **D01-O4:** `RuntimeControls.useApiConnection()` can reuse an in-flight old controls request after connection/token rotation; command/mention discovery has similar additive exposure. Access mutations remain gateway-authoritative, so this stays unpromoted pending E02.
- **D01-O5:** recovery mutations are not transparently replayed after disconnect. The UI retains retryable recovery state; ambiguous apply/idempotency semantics remain an E02/D6 question.
- **D01-O6:** transcript/diff/LaTeX rendering is bounded/turn-scoped; packaging and PTY validation are explicit, auditable surfaces.
