## Architecture judgement and preserved strengths

**Provisional Keep + Simplify.** Keep the bounded repository catalog/discovery model, explicit context-repository manifests, canonical knowledge writer publication path, prompt budgeting before provider dispatch, progressive skill disclosure, managed-WebUI prompt validation, configured provider/runtime ownership, and bounded Dream/evaluator prompt overrides. Simplify the remaining seams by making every prompt/skill read use one resource-policy owner, making runtime skill validation match the shipped authoring contract, deriving prompt guidance from actually registered capabilities, routing auxiliary semantic work through the configured provider, and placing every Dream mutation inside the same audit/restore transaction.

## Smaller alternatives and simplification

The evidence does not support replacing the context/skill subsystem wholesale. The smallest coherent simplification is to reuse owners that already exist: one resource-policy path resolver for every instruction source, one skill metadata validator for authoring/package/runtime, one effective agent-workspace locator for bundled skills, one capability-derived prompt description, one configured provider route for auxiliary model calls, and one Dream mutation ledger. These changes reduce parallel contracts rather than adding new frameworks.

### K01-STG-F01 — New staging-only conditional P2: bundled-skill summary path can resolve a different selected-project file

**Source/contract:** `SkillsLoader.build_skills_summary` still labels a skill with `entry["source"] == "builtin"` as **Built-in skills**, but since staging `:279–306` shows it as `skills/<name>/SKILL.md` even when a separate project is selected. `ContextBuilder` supplies its effective project root via `nanobot/agent/context.py:238–243`. File tool `_resolve_with_extra:258–285` resolves a relative tool path against `current_tool_workspace(...).project_path` (backed by `security/workspace_policy.py:19–29,106–123`). `ReadFileTool._execute_read:675–684` first resolves that relative path; `_builtin_skill_read_path:480–494` is used **only if the resolved project file does not exist**. Therefore a selected project containing `skills/<bundled-name>/SKILL.md` can make the read return project content while the agent's summary describes the item as bundled. The loader's source-priority discovery checks the **agent workspace** plus explicit extra libraries; it does not automatically treat every selected project's `skills/` directory as a discovered/shadowing skill source (`skills.py:60–74,101–135`). If the project was explicitly registered as a skill library, that could legitimately shadow the builtin and remove the affected builtin summary entry; the finding applies to a separate, non-registered selected-project skill file.

**Trigger/consequence/confidence:** a distinct selected project, a conflicting path under that project, a bundled skill that has not been shadowed in loader discovery, and an agent following the displayed progressive-load `read_file` path. The read returns the project file, not the skill content whose source label, metadata and description were advertised. This can introduce incorrect/provenance-confused instructions if project content is untrusted or unrelated. It is **not** a demonstrated filesystem escape, automatic arbitrary tool invocation, or observed malicious prompt injection: the file is ordinarily inside the chosen project's authorized read scope. P2 applies conditionally to instruction-source integrity and trust. The changed summary and path precedence are confirmed by source; no runtime reproduction was performed. Existing updated tests check display strings only, **not selected-project same-path collision or returned file identity**. This newly introduced risk is distinct from original K01-F03 invalid metadata shadowing.

**Smallest alternative:** when a different project is selected, retain the source-qualified **absolute bundled path** previously shown (subject to the existing explicit built-in read allowance), or add a source-qualified built-in-only resolution path that cannot be captured by a local project file; keep relative `skills/<name>` for the agent workspace where loader precedence already screens agent-workspace conflicts. Add a narrow test covering an unrelated project with `skills/<builtin-name>/SKILL.md` and asserting both summary provenance and actual `read_file` target; separately test that an explicitly registered library's intentional shadowing still behaves as designed. Do not change general resource-policy restrictions or grant a new path privilege to fix a display mismatch. **Decision route:** existing K01-Q4 / P01-C01 / D2,D4,D7, with source-of-truth ownership in K01 and file-path resolution in S01/T01.
