## Architecture judgement and preserved strengths

**Provisional Keep + Simplify.** Keep the authenticated mutation transport, per-chat/per-turn lifecycle identity, canonical completion fences, history lineage guards, explicit workbench/session ownership and safe rendering boundaries. Simplify repeated asynchronous UI ownership around one generation/identity discipline, one queued-prompt sendability predicate, an explicit optimistic-persistence state machine, and turn-local completion projection. The evidence does not justify replacing React state management wholesale or moving browser authority into the client.

Important strengths to preserve include same-request-id WebUI mutation replay after reconnect, no blind resend after unknown ordinary-message disposition, turn-correlated streaming/activity state, session/history read-version fences, cancelled settings/model/QR reads, workbench pane normalization, conversation-key camera resets, magic-byte/media bounds and safe HTTP(S)/React-node rendering.

## Promoted findings

| ID | Priority | Classification | Trigger and bounded consequence | Smallest useful alternative |
| --- | --- | --- | --- | --- |
| **U01-F01** | P2 | Attachment-only queued guidance skipped by automatic FIFO flush | While a run streams, an attachment-only prompt is validly queued. Idle auto-flush selects only rows with non-empty text, so the item can strand and a later text row can skip ahead. No attachment loss is proven. | Reuse one sendability predicate (text OR attachments) for manual/automatic flush and preserve first eligible FIFO order. |
| **U01-F02** | P2 | Stale generated-asset pagination crosses session switch | Session-A load-more resolves after the open sheet has switched/reset to session B; the late A page appends into B's gallery. Same-user cross-session display/integrity contamination only. | Fence pagination by session/request generation or abort it on session change/close. |
| **U01-F03** | P2 | Channel setup async completion crosses selected channel | Validation/configuration for A finishes after the reused setup surface changes to B, repopulating B with A's validation/notice/busy completion. Server mutation remains targeted to A. | Key the surface by channel or ignore completions whose feature/request generation is stale. |
| **U01-F04** | P2 | Skill mutation completion crosses selected skill | Mutation for skill A settles after B is opened; A can merge into B detail, clear B busy state, or close B after A deletion. Backend target remains A. | Fence mutation completion/finally by skill identity/generation or remount the detail sheet per skill. |
| **U01-F05** | P2 | Failed sidebar persistence remains optimistic and unsaved | sidebar.update rejects/times out while socket stays open. The snapshot is requeued but neither retried nor rolled back/surfaced, so reload can silently lose the displayed change. | Add explicit retryable/terminal persistence handling with bounded retry and visible reconciliation. |
| **U01-F06** | P2 | Empty turn stamps completion metadata onto older legacy assistant | A turn ends without an assistant row; backward completion scan crosses the current user row and can select an older assistant lacking turnId, misattributing latency/usage/context/completion time. | Stop at the current user boundary; only apply missing-turnId compatibility inside that turn. |

## Cross-cutting simplification direction

The repeated F02/F03/F04 pattern is not a reason for a new framework. A small reusable request-generation/identity helper (or keyed remount where state ownership is naturally component-local) would remove three stale-completion classes while preserving current APIs. F01 should share the existing manual-send predicate instead of adding queue branches. F05 needs a tiny persistence state machine rather than more optimistic flags. F06 belongs in the projection helper itself, not in every caller.
