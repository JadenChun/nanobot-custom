## Observed ownership and positive mechanisms

1. `AttachmentIngress.accept_batch` uses MIME/count/byte policy, stages each item, and discards staged files when rejecting the batch. `commit_batch` turns staged files into content-addressed records after admission.
2. `AttachmentStore` stages private files, hashes and renames/copies commits with fsync; distinct logical records may share a blob. Explicit absolute external paths are legacy compatibility, not automatically copied, and require subsequent lifecycle review.
3. `UploadRegistry` holds short-lived process-local bindings; `bind` checks installation identity and session identity, and pins formerly session-neutral uploads on first binding.
4. `InboundMessage._adopt_media` bridges adapter media paths; canonical identities are reused when existing bound records match. `store_inbound_records` is a WebUI compatibility wrapper, not an independent storage owner.
5. `prune_unreferenced` scans session JSONL references and preserves referenced/recent blobs; `migrate_legacy_media` rewrites legacy user events with backups when not in dry-run mode.

## Provisional findings — NOT coordinator accepted

**M01-P01 (provisional P2): migration dry-run mutates the attachment store.** `lifecycle.py:migrate_legacy_media(dry_run=True)` still calls `_migrate_event`, which calls `ingress.accept_path` and `ingress.commit_batch`; `store.stage_path/commit` create staged, content-addressed and sidecar files before the outer `if not dry_run` guard skips only the JSONL rewrite/backup. Trigger: legacy user media event with an accessible media-root path. Actual side effect: disk writes despite the dry-run contract; existing dry-run test checks only unchanged session text. Smallest alternative: pure preflight planning or an explicit non-mutating validation path before actual commits. Confirm real CLI/caller entrypoints before final promotion; source mechanism is direct.

**M01-P02 (provisional P2 / hygiene, priority conditional on retention expectations): orphan cleanup does not remove metadata sidecars.** `lifecycle.py:prune_unreferenced` skips files with `.json` suffix; it unlinks eligible content files without unlinking `<hash>.json` written by `store._write_sidecar`, and empty-directory removal then cannot remove directories containing sidecars. Trigger: pruning an old unreferenced blob. Consequence: permanent orphan sidecar files unless another owner cleans them. Consider unlinking the specific sidecar only after the associated blob deletion, with shared-blob/extension implications checked. Caller activation and retention policy need investigation.

**Other questions, not yet promoted:** `ingress.commit_batch` may partially commit then return a rejection, leaving earlier blobs for deferred retention cleanup; whether this violates transactional admission depends on caller semantics. `adopt_media_paths` may preserve external absolute paths intentionally, requiring examination of post-admission grants and future readability. MIME is based on supplied MIME/extension for non-image types; don't call that a vulnerability without the consumer and trust model. `accept_batch` decodes base64 before decoded-size enforcement; check upstream request caps and memory bounds before deciding whether this is material.
