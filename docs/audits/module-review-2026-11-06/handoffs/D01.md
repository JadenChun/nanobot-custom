### Architecture observations

- The Python desktop pipe is a strict bounded NDJSON protocol: duplicate keys, non-v1 frames,
  unknown fields/operations and oversized frames are refused with bounded error codes.
- Desktop admission is independently revalidated in the child. Managed desktop mode requires
  loopback gateway/WebSocket listeners, WebUI authentication, non-conflicting ports, provider
  setup and runtime preflight.
- Tauri preserves uncertain-dispatch semantics instead of assuming a timed-out write did not
  happen. Start/stop/status results remain bound to the captured lifecycle handle; quit refuses
  to exit while start/stop disposition is unknown.
- Native shell authority is fail-closed: private runtime/socket directories, kernel singleton
  lock plus session-bus owner verification, generated ACL that denies Tauri commands to the
  remote gateway origin, constrained navigation, and WebUI cleanup confirmation before
  hide/destroy.
- Desktop setup UI mirrors the controller's selection/admission/stop locks and renders paths/status
  through text content; it does not install or update the backend.
- TUI desktop connection resolution validates the selected gateway identity and loopback HTTP/WS
  endpoints before exposing credentials to the client. TUI detach/exit intentionally disconnects
  only the terminal client; the selected Desktop backend remains persistent.

### Supplementary lifetime reconciliation

A bounded caller/context read of `nanobot/gateway/runtime.py` confirms that
`release_desktop_lease()` intentionally **retains persistent gateway lifetime**, while
`stop_desktop()` verifies the captured process birth identity, selectors, command/listener proof
and signal target before stopping. Therefore `DesktopAdapter.close()` releasing its lease is not
evidence of an orphaned managed gateway.

The earlier U01 handoff shorthand “HostWebSocket pre-open close” was traced to the TUI
`NanobotClient` lifecycle; there is no literal `HostWebSocket` symbol in the pinned source.
The targeted `tui/src/protocol.ts` read shows an async desktop resolver rechecks
`closedByClient` before constructing a WebSocket, and the direct-URL path has no await between
the close guard and socket ownership assignment. That deferred question is resolved as
**no finding**. `tui/src/protocol.ts` itself remains only partially read and receives no D01
primary-body credit yet.
