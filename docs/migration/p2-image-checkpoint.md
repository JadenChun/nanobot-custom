## Intentional provenance correction

The historical output-free directory scan could misattribute another process's newly generated image. It cannot simultaneously preserve that behavior and prove invocation association. The bounded planner identified this contradiction; the canonical adapter now requires a child-emitted image reference correlated with new/changed content. Exact paths must stay in the configured generation directory. Scanning remains available for emitted relative paths/basenames and requires a unique matching candidate. Timestamp-only changes, stale images, outside-root references, output-free unrelated files, ambiguous matches and file replacement during capture are rejected. Basename correlation is weaker than a structured generation receipt; no unsupported CLI flags or cryptographic identity claim is introduced. The old tool/tests remain baseline evidence, not a runtime registration.
