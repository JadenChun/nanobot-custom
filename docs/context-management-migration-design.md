# Context management migration design

Status: recommended architecture for implementation review, not implemented or approved product defaults. Date: 2026-09-08. Local baseline: staging `4aa562d9`, migration branch `codex/upstream-migration`. Upstream baseline: `f47b8f23155ddec23cfb80ec001b544d495df89c`. The isolated P0 mapped baseline retains its immutable 866-pass/2-failure staging result; its 876-pass overlay is P0-CANDIDATE-ACCEPTED, so P1 replacement may begin under the parent plan. See the [P0 baseline](migration/p0-baseline.md). This design extends the [source study](upstream-context-and-continuation-study.md).

## Decision and boundaries

Adopt upstream's `ContextGovernor`, transcript builder, accepted-history/pending-delta model, and provider conversation controller as the single context engine during the upstream migration. Adapt their persistence and permission boundaries to this fork. Keep the local shared prompt-budget guard and session concurrency protections. Do not retain upstream governance and local history-dropping engines as competing reducers in the same request path.

The intended behavior is a long task that retains its objective, constraints, decisions, evidence references, and next steps across repeated compactions and reloads. Context management creates recoverable working memory; it does not grant permission, start a goal, schedule another turn, or retry an interrupted mutation. Foreground role routing, explicit tool capability limits, worker write scopes, external context repositories, and the crawler remain authoritative.

Rejected alternatives:

- Continue dropping old turns as normal pressure relief: bounded requests but irreversible loss of task facts from model context.
- Treat `MEMORY.md`/`HISTORY.md` as task checkpoints: they have different scope, consolidation receipts, and update timing; neither identifies the exact transcript prefix replaced.
- Store only provider response IDs or opaque native compaction: unsuitable as the portable restart or fallback source of truth.
- Replace session history with a summary: weakens audit, rollback, and recovery; creates an avoidable data migration.
- Introduce a database and multi-file transactional journal now: existing locked atomic JSONL snapshots can commit transcript and checkpoint together. Reconsider only if measured session size makes snapshots impractical.

## Evidence and integration map

The current implementation already has detached deterministic reductions and guards, although some class docstrings still describe LLM memory compression. `ContextBudgetManager.enforce_budget` compacts tool results, drops turns, and invokes deterministic `reduce_messages_to_budget`; it deliberately does not recursively call an LLM. Local `maxTokens.input` is a **total logical context budget including output reserve**, despite its name.

The [custom-change audit](migration/custom-change-audit.md#core-05) also establishes an initialization hazard: pinned upstream `MemoryStore._maybe_migrate_legacy_history` creates `history.jsonl` and renames legacy `HISTORY.md` to a backup. Recover the fork's pending consolidation receipts before invoking that constructor/migrator, and explicitly map the archival format and legacy readers. Importing upstream memory code is not a passive read of existing files; disabled Dream alone does not establish that legacy-history conversion is disabled. This clarification changes migration sequencing, not the checkpoint/source-transcript authority below.

## Transcript and projection contracts

Define three separate objects:

1. **Source transcript:** durable ordered session events plus immutable artifact references for offloaded results. Raw means retained application evidence after explicit persistence/privacy sanitization, not provider secrets or hidden reasoning. New messages receive unique `_event_id` and `_run_id`; content is not deduplicated by value. Tool execution IDs include run and call identity. A generation change identifies explicit reset/replacement, not compaction.
2. **Checkpoint:** derived working memory covering `[0, boundary)` in a particular session generation. Boundary is exclusive and measured in source events, never model-message indexes, tokens, or the memory-consolidation offset.
3. **Model projection:** detached current policy/system instructions + validated checkpoint + source suffix + current runtime context and scoped evidence. Normalize provider message shapes only here. A provenance map survives filtering, hidden events, normalization and merged model messages so boundaries never rely on `len(projected_messages)`.

Enabled sessions construct history from source events independent of `last_consolidated`; the latter remains a long-term memory archival cursor. Preserve scheduled-history filtering and `HistoryMode.FRESH`; fresh requests must not import an unrelated session checkpoint. Runtime instructions, authorization grants, counters, role identity and mutable capabilities are rebuilt from current structured state, not summarized as authority.

Compaction never modifies source content or generation and cannot erase the newest user instruction. Close tool-call/result groups before a boundary; never summarize an assistant call while retaining only its result in the suffix. Pending calls and newly generated/unaccepted results stay in the delta. If a boundary would split a tool group, move it backward. After a provider accepts a completed group it can become eligible at a later iteration. Preserve at least the newest user-led turn when feasible; irreducible active content is a controlled failure, not silent truncation.

Projection repairs may represent persisted interrupted/missing results with an explicit unavailable/unknown-outcome marker. They cannot fabricate successful execution or backfill a still-running live call. Preserve provider IDs/signatures needed for legal replay; an incompatible provider-specific block is converted only by a tested adapter or triggers a controlled compatibility error.

## Artifact storage and retrieval

Recommended first release: offload large **text tool results**, retain inline raw content in the source transcript during the rollback window, and use compact artifact references only in the projection. This deliberately improves model capacity before optimizing disk size. Reference-only source persistence or durable multimodal blobs require separate retention/privacy acceptance; legacy truncations and image placeholders remain labeled unavailable.

Runtime-owned artifacts live under a configurable private state directory outside product and external context repositories. Assign a persisted workspace UUID and session-generation namespace; use unique artifact IDs, not tool-call IDs or sanitized session names as unique keys. Stable model references are `artifact:<id>` resolved through the store, never absolute paths. Manifest entries include version, workspace/session/generation/run, originating event/tool execution, MIME type, byte length, content digest, creation time and source access label. IDs are opaque, not access tokens.

The runtime writes bytes to a same-filesystem temporary file, flushes/fsyncs, atomically installs the immutable blob, then publishes its manifest/reference in the session commit. Sync parent directories where supported; document weaker platform guarantees. No dangling reference is committed before the blob is durable. Identical retry event IDs reuse a verified blob; different outputs cannot overwrite it. Read-time digest/length mismatch is corruption. Unreferenced crash leftovers are garbage-collection candidates after a grace period.

Provide bounded range/line retrieval through the existing registry/capability pattern. Only explicitly granted artifacts are visible to child runs; foreground access requires the current session/workspace binding. Recheck current source policy on reads, including revoked external-repository access. Runtime persistence is an internal write, not a worker permission to write arbitrary state paths. Workers cannot choose destinations or enumerate other sessions. Validate identifiers and offsets, use no-follow/containment checks, reject traversal and symlink escapes, set private directory/file permissions, and cap bytes per retrieval. Retrieval outputs carry the original artifact identity and are exempt from recursive re-offloading, while still obeying the request budget.

Crawler results may reuse immutable crawler evidence when the store can verify ownership, integrity and retention; otherwise snapshot authorized text. External repository paths remain source locations with revision/digest provenance, not portable artifact IDs. Moving the workspace only requires rebinding the private state root; copying a session without its store yields an explicit unavailable artifact, never a guessed filesystem lookup.

Default recommendation: no automatic eviction of artifacts referenced by retained transcripts/checkpoints; no TTL-based bucket deletion. Active runs, pending tool outcomes, admitted recovery and active goals pin dependencies. Persist pins/references before retrieval or checkpoint publication, and serialize publication with garbage collection under a store lock (lock order: store, then session; never hold either across network work). Conservative reachability scanning is preferable to fragile reference counts initially. Expired run leases alone cannot remove transcript-reachable artifacts. Delete only unreferenced objects after a 24-hour grace period; explicit user deletion/reset follows documented retention policy and overrides pins by terminating affected work. Disk pressure stops offloading and emits a content-free diagnostic; it never evicts active evidence.

On write failure keep the raw result. Send inline only if the final request fits; otherwise stop with a recoverable context/storage error. On missing/corrupt retrieval return a bounded typed error and recover from retained inline source when available. Do not rerun a side-effecting tool to recreate evidence.

## Checkpoint schema and commit protocol

Add versioned metadata `context_checkpoint` containing:

- `schema_version=1`, `checkpoint_id`, `session_generation`, `boundary`, `boundary_event_id` (null at zero), canonical `prefix_digest` and digest algorithm/version;
- `parent_checkpoint_id`, creation timestamp, producing model/provider identifiers, summary format version and summary text;
- referenced artifact IDs, summary-call usage totals and source revision for audit.

Digest the canonical persisted event representation over the covered prefix; specify stable UTF-8 JSON serialization with sorted keys and fixed separators. Internal event fields participate; transient projection fields do not. Checkpoint artifact lists are runtime-validated against authorized source references, not accepted from model output unchecked. `boundary <= durable_event_count`, matching generation/digest, supported versions and nonempty bounded summary are mandatory. Unknown/malformed checkpoints are ignored with a diagnostic; source evidence remains usable and receives ordinary guarded rebuilding.

Use one per-session execution lease across gateway/CLI writers and short existing file locks for commits. A fenced lease token prevents an expired owner from committing tool dispatch or checkpoint state after a new owner acquires the session. An old in-flight external call may still finish: lease loss prevents new dispatch, and recovery records its outcome as uncertain unless reconciled. Do not claim that fencing can cancel external side effects. The existing append-merge path may remain for independent metadata/detail writes, but governed execution and checkpoint mutations require strict CAS; Staging protected replacement saves with `expected_revision`, but the integration merge does not yet enforce that protection. Restore revision/generation checks first; then add strict governed CAS rather than relying on ordinary append merging. Dormant source/checkpoint contracts are tracked in [P4 work in progress](migration/p4-source-contract-work-in-progress.md).

Commit sequence:

1. Append the user event durably before generation. Persist assistant calls before tool dispatch; persist each result as it becomes known. Persist events idempotently by event/execution ID. Final turn saving must not append these events again. RunStore can refer to committed event IDs and reconcile after restart; it is not a second transcript authority.
2. Snapshot generation, revision, lease token, checkpoint ID, source prefix and proposed closed boundary. Release file locks before summary work. Reserve summary budget. Keep all source events available while constructing the candidate.
3. Validate summary, references, schema and rebuilt request budget. Acquire commit locks, reread disk, and require unchanged generation/revision/checkpoint/lease. Reject stale candidates; reload and rebuild. First version rejects even append-only revision changes to simplify correctness.
4. Atomically replace the JSONL snapshot containing both covered source events and checkpoint metadata, incrementing revision only. Existing file fsync plus replacement is retained; add directory sync for supported durability targets. Publish the new in-memory projection only after commit succeeds. Invalidate provider state before any request using the new prefix.

A crash before replacement retains the old checkpoint; after replacement reload selects the new valid checkpoint. Artifact orphans are harmless. Cancellation discards an uncommitted candidate; a committed checkpoint remains valid even if the subsequent model call is cancelled or fails. Metadata-only ordinary saves must not overwrite reserved checkpoint/lease fields with stale cached values. `/new`, trim and retention operations invalidate checkpoints or explicitly remap and revalidate boundaries; first release invalidates them. Treat corrupt existing JSONL as a recoverable storage error for governed sessions, not an empty session that can overwrite evidence.

Restart rebuilds the projection from checkpoint plus raw suffix and discards provider handles by default. It records dispatched calls without durable outcomes as interrupted/unknown, never automatically replays them. Full tool reconciliation and recovery admission belong to the execution migration; context migration must expose these facts without launching work.

## Provider state and request capacity

Use upstream conversation-state types/controller with a local adapter. State is scoped to workspace, session generation, execution owner, concrete provider/account/endpoint, resolved model, projection epoch and relevant runtime/tool-schema fingerprint. Keep it ephemeral initially. Provider-native compaction is optional and must expose an exact covered boundary plus portable summary before it can replace a durable checkpoint.

Maintain `H` (acknowledged model prefix), `D` (new unsent events/projection delta), a raw boundary and provenance mapping. Distinguish the stable local history eligible for initial compaction from remote acknowledgment: on a new process there is no acknowledged remote prefix. A request advances remote `H` only after a validated successful response, not when transport begins. Subsequent tool outputs enter `D` exactly once. A timeout, partial stream or ambiguous response does not advance the boundary; invalidate the uncertain handle and reconstruct a fresh full projection. Do not redispatch tools from a partial response. This guarantees local event preservation, not exactly-once remote model billing.

Invalidate handle and cached usage on summary replacement, any accepted-prefix repair/offload/render change, reset, policy/tool/runtime-prefix change, provider/account/model switch, unknown response outcome or ownership change. Only append-only compatible requests may reuse state. Failed summary validation does not advance either boundary. Fallback must reselect a concrete provider, rebuild/recount its full portable projection and clear state; never forward another provider's handle. Switching back after cooldown is also a new epoch. If fallback requires more reduction, return control to governance rather than silently sending an oversized payload from inside the provider wrapper.

For **every concrete transport attempt**, including streaming, fallback, retries with transformed media, summaries and memory auxiliary calls:

`measured_input(finalized_request, tools, protocol_overhead) + completion_reserve + safety_buffer <= min(configured_total_budget, known_model_window)`

Use the local total-budget interpretation unchanged; migrate config aliases explicitly rather than double-subtracting reserves. Finalize system/runtime blocks, effective tool definitions, tool choice/structured schemas, media conversions and provider normalization before measuring. Recheck after hooks. Match usage to the complete request fingerprint and model; old usage cannot certify a changed request. For resumed requests measure server-held context plus delta, not merely bytes sent. If that cannot be bounded, use a stateless full projection. Token estimates are estimates of the exact request shape, not a claim of exact provider tokenization; preserve the 1,024-token safety buffer initially and record the measurement source.

Summary generation is an explicit bounded auxiliary operation, outside the deterministic final guard. No recursive summarizer from a budget assertion. Recommend one summary attempt per pressure event, a 2,048-token maximum output further capped by available rebuilt-request space, and at most four sequential bounded chunks for an oversized prefix. Chunk only closed groups, fold prior summary plus the next disjoint chunk, count every call, and commit only the final validated candidate. The candidate covers exactly those consumed events. If even one group cannot fit with authorized artifact references, or output is empty/truncated/invalid, fail without advancing its boundary. Enforce an auxiliary call/token ceiling and ordinary timeout; no unbounded recursive summarization or retry loop. After offloading and summary, an oversized current user message, tool schemas or policy prefix produces `PromptBudgetExceeded`/equivalent typed stop with zero main transport. Enabled mode does not silently drop task history as a final fallback.

## Summary content and trust

Require a compact structured working-memory document with objective and success criteria; explicit constraints and exclusions; decisions with reasons; completed work and validation evidence; current progress; stable artifacts with provenance; unresolved questions/blockers; next concrete actions; and pending tool execution IDs/status, including unknown outcomes. Carry the previous checkpoint forward while incorporating only the new covered prefix; label uncertain or contradictory facts and preserve later user corrections. Deterministically attach current structured pending state to the projection even if a summary omits it.

Summary text is untrusted derived conversation data. It cannot create an approval, widen worker writes, change roles, override tool capability policy, authorize an external action, mark a goal complete, or reset usage. Runtime checks remain outside the model context. Summaries and tool artifacts are injected as data, not privileged system instructions; source instructions inside them retain their original trust level. Store only task-relevant content; never log full summaries, prompts, retrieved excerpts, credentials or provider handles.

## Idle compaction and goal integration

Keep idle compaction disabled (`TTL=0`) by default. If later enabled, use the same engine/schema/budget/commit protocol, not a second summarizer. Eligibility requires elapsed idle TTL, no active run or live tools, no pending user input, no admitted recovery and no unresolved approval execution. Snapshot user-activity revision and generation; compute outside locks; commit only if both and the lease/checkpoint revision still match. Foreground admission increments activity revision before running and cancels/discards idle work. Idle jobs use a bounded queue, one job per session, backoff on failure and a separate cost ceiling. Never change the user-activity timestamp merely because a summary was written. Disable scanner during shutdown and treat cached-session state as advisory.

A future goal runtime may supply an immutable goal ID/revision, objective, structured status, limits and usage counters to `TurnContext`; context summaries can reference these and the store can pin their evidence. Each compaction/auxiliary model call reports usage to the existing run accounting and future goal ledger. Context checkpoints never infer goals from chat, reset budgets, schedule continuation or suppress final messages. Approval, cancellation, policy blocks and exhausted limits remain execution boundaries even when a checkpoint is valid. Automatic continuation, goal-wide total-cost policy and goal restart admission belong to optional P8 follow-on work outside the parent migration definition of done. Neither their implementation nor an explicit deferral decision is required to complete the base migration and agreed context enhancements.

## Rollout, rollback and operational gates

Ship additive readers and disabled feature flags first. Back up representative sessions; verify imported upstream tests plus local invariants. Add shadow projection/measurement without provider calls or writes; optional summary evaluation must be explicitly metered. Canary opt-in sessions with text offloading and checkpoint writes while retaining raw inline tool content. Enable stateless pressure compaction first; enable provider state only after package 4 passes. Keep idle disabled throughout the initial rollout.

Rollback stops new compaction and invalidates in-memory provider state; a compatibility reader can use full retained source with the legacy bounded projection, ignoring checkpoint metadata. Stop all newer writers before downgrading to an old binary; mixed versions must not concurrently write governed sessions. Preserve unknown additive metadata on reads but do not rely on old code preserving checkpoint correctness on writes. If old writers ran, invalidate their checkpoints and rebuild from source on re-upgrade. Maintain source-inline retention through the supported downgrade window; reference-only transcripts later require a checked export/materialization step before old binaries can read them. Backups and restored sessions must include artifact state and bindings. Rollback cannot restore pre-migration truncation or deliberate user deletion.

Emit content-free structured events for compaction start/commit/discard/failure, boundary/checkpoint identifiers, revision conflicts, provider invalidation reasons, token measurement source, before/after sizes, auxiliary usage/latency and artifact storage failures. Hash or pseudonymize session identifiers; keep paths, full payloads and handles out of telemetry. Alert on repeated compaction failure, missing referenced artifacts, CAS conflict spikes and source/projection digest mismatch. Existing unrelated logging of prompt previews is not evidence that new context logs may expose content.

Recommended defaults requiring implementation/config review, rather than assumed user approval: text-only offloading with inline source retention; offload each text block exceeding 16,000 characters and cap its reference preview at 1,200 characters (measure UTF-8 bytes separately for storage quotas and manifest byte lengths). These are per-block limits; the aggregate finalized request, including all blocks, reference metadata, tool definitions and reserves, must still pass the shared token-budget guard. Other defaults: pressure trigger at 90% of available request capacity and target at 60% (hard guard remains 100%); 2,048-token summary output cap with four bounded chunks; 1,024-token safety buffer; no referenced-artifact eviction; 24-hour unreferenced grace period; no persisted provider handles; idle TTL zero. Validate ratios against small windows and fixed policy/tool costs; fail early when no room exists.

Remaining gates are concrete: select the private artifact root and deployment backup policy; choose per-session auxiliary cost/time ceilings and model after measured evaluation; confirm provider finalized-payload counting APIs and media/signature compatibility; document supported filesystem durability and multiprocess lease implementation; choose retention/delete semantics and any future multimodal persistence; set corpus cost/latency thresholds and downgrade support window. These gates do not reopen transcript authority, strict CAS, scoped retrieval, structured policy authority or no-replay invariants. Goal scheduling/recovery policy remains owned by the separate execution design.

Readiness follows the parent plan: P0 source accounting and archived staging baseline execution are complete (61 files, 868 cases, 866 passed and 2 failed). The [candidate fix supplement](migration/p0-fixes.md) records the P0-CANDIDATE-ACCEPTED overlay that closes those two defects with 876 passing cases. Per-finding `NOT-RUN` labels describe still-unrun migration replacement/differential validation, rather than a claim that the staging baseline did not run. This does not authorize context enablement or deployment. Resolve the context gates above before the affected package or enablement; resolve live release choices at parent P6/P7. Routine review of recommended settings within authorized scope does not require repeated permission.
